## 1. 系统概述与运行形态

前端是一个 **Vue 3 单页应用**，构建产物输出到后端静态目录 `app/static/`，随 FPK 包一起部署。有两种运行形态，架构多处为其做了显式设计：

| 形态 | 入口 | 关键影响 |
| --- | --- | --- |
| **飞牛桌面内嵌**（主形态） | 应用以 **iframe** 嵌入 fnOS 桌面（`app/ui` 声明 `fn-finstat.main`），可能处于 fn Connect 子域/独立端口（**跨域**） | 不得假设能读宿主 localStorage → 主题探测走多源降级链；SDK 动态加载并带超时竞速；接口前缀运行时推导 |
| **独立访问 / 本地开发** | 直接浏览器打开，Vite dev server（5173）代理 `/api` 到后端 8090 | 主题降级到系统偏好；SDK 检测非 iframe 自动跳过 |

**接口前缀在运行时从页面 URL 推导**（对应部署向导参数 `wizard_api_base_path` 可改），**禁止构建期写死 base**——这也是 Vite `base: "./"` 的原因。改前缀无需重新构建。

## 2. 技术选型与取舍

| 项 | 选型 | 取舍理由 |
| --- | --- | --- |
| 框架 | Vue 3.5，一律 `<script setup>` | 不用 Options API |
| 构建 | Vite 8 | 产物输出 `../app/static`，函数式 `manualChunks` 拆包 |
| 图表 | ECharts 6，按需注册（`src/utils/charts.js`） | 独立 chunk（约 628KB）利于长缓存 |
| 宿主集成 | `@trimjs/web-app`（飞牛官方 SDK） | 主题探测与目录授权；动态 import + 超时竞速（实测无响应宿主会永久挂起） |
| 状态 | 原生 `reactive`/`ref`，**无 Pinia/Vuex** | 全局共享状态只有 4 个（见第 6 节），引状态库收益为负 |
| 路由 | **无 vue-router** | 10 个面板 `store.tab` + CSS 切换（见第 3 节），无 URL 路由诉求 |
| 语言 | JavaScript + JSDoc，**无 TypeScript** | 与后端契约经统一响应结构约束 |
| 请求 | 自封装 `src/api/client.js`，**无 axios** | 需深度定制：运行时前缀推导、旧 WebView 兼容的超时合并、错误码翻译 |
| UI 库 | 无 | 视觉体系为自研设计令牌（`docs/界面设计方案.md`），反馈组件自研三件套 |
| 质量 | ESLint 9（flat）+ Prettier 3 + Node 原生测试 | `npm run lint` / `test` / `build` 接入 CI 门禁 |

> **1.1.0 现状核对**：上表的四项「无 vue-router / 无 Pinia / 无 TypeScript / 无 axios」在 1.1.0 仍成立。`App.vue` 仍用 `store.tab` 驱动面板、无路由库；全局状态仍只用 `reactive`/`ref`（`store.js`）；全部请求仍走自封装 `api/client.js`，没有任何 axios 依赖；源码仍是 JavaScript + JSDoc。1.1.0 新增的账本/家庭/借贷/报销/审计/储蓄/教练等面板与卡片均沿用同一套约定，未引入路由、状态库或类型系统。

## 3. 总体架构与应用外壳（`App.vue`）

```
App.vue（.app-shell）
├── aside.sidebar（>860px）/ nav.mobile-tabbar（≤860px）   ← 导航双形态
├── header.topbar（当前页标题/描述 + 快捷导入 + NotificationBell + ThemeToggle）
├── main.container
│   ├── DashboardPanel / QueryPanel / ConsumptionMapPanel / BillsPanel
│   ├── AssetsPanel / FamilyPanel / LoansPanel* / CategoryPanel
│   ├── ImportPanel / SettingsPanel                          ← 10 面板，默认全部常驻挂载
└── AppToast / AppConfirm / AppLoading                       ← 全局反馈组件，仅挂载一次
```

**面板切换机制**：`store.tab`（字符串）驱动。除 `LoansPanel` 外，9 个 Panel **不用 v-if/v-show**，而是根元素绑 `:class="{ active: store.tab === 'xxx' }"`，由 CSS `.panel { display:none }` / `.panel.active { display:block }` 切换（收益：状态天然常驻、切换零开销）。代价是多个面板同时存在，因此各 Panel 内部用 `watch(() => store.tab === 'xxx', active => active && load(), { immediate: true })` **首次激活才发请求**，图表用 `useChart` 的 `canRender` 规避 `display:none` 下的 0 尺寸渲染。

> `LoansPanel` 是唯一例外：在 `App.vue` 中以 `<LoansPanel v-if="store.tab === 'loans'" />` 条件挂载（其余面板用 `.active` 常驻）。它依赖 `onMounted` 触发首次加载，因为只在激活后才会进入 DOM——这条「常驻 vs 条件挂载」的分裂是有意为之（借贷台账较重、且不在移动端高频路径），其余 9 个面板仍遵循 `.active` 常驻约定。

导航配置 `NAV_GROUPS` 分两组：账本（dashboard / query / map / bills / assets / family / loans）与数据（import / categories / settings）；移动端 `MOBILE_TABS` 排除 categories、map、loans 三项低频/分析类。入口 `main.js` 先 import theme 与 fnos 再挂载应用，保证主题同步先于首帧。

**主题切换常驻**：`ThemeToggle` 在桌面端常驻于侧边栏底部（`sidebar__footer`），移动端侧边栏整体隐藏时改由顶栏提供（`topbar__theme`），任何形态下都能一键在 auto→light→dark 间循环；配色主题（见第 10 节）则在设置页「外观」以色板圆点选择。顶栏另常驻 `NotificationBell`（通知铃铛 + 未读角标 + 下拉面板，见第 5 节）。

## 5. 组件体系

**页面面板**（`src/components/`）：

| 组件 | 职责 |
| --- | --- |
| `DashboardPanel` | 统计看板：概览卡 + 月趋势/分类饼图；子区块 `BudgetSection`（预算 vs 支出）、`HeatmapSection`（日支出热力图）、`YearCompareSection`（年对比）各自独立加载；`HealthCard`（财务健康评分，分项公式由后端下发、可展开口径）与 `ForecastSection`（现金流预测 + 支出结构拆分）作为内嵌子组件接入；AI 报告走 `AIReportModal`（生成预览 → 归档两步流，内置极简 Markdown 渲染，不引第三方库） |
| `QueryPanel` | 对话式查账（T-6.2）：一句话提问 → 回答卡（结论 + 分组占比条 + 「依据」折叠区），保留最近 3 轮追问上下文；支持「存为筛选」把口径交给 `BillsPanel` 复现（`store.billsFilterHandoff`） |
| `ConsumptionMapPanel` | 消费地图：刻意不画地理边界（合规），用 Scatter 在直角坐标系按经纬度画城市气泡；`charts.js` 不注册 GeoComponent，零行政边界数据依赖 |
| `BillsPanel` | 流水工作台：筛选/排序/分页、回收站模式、多选 + 吸顶批量条、AI 归类、导出；子组件 `BillModal`（新增/编辑）、`RowActionsMenu`（行内操作收纳）、`ReimbSection`（报销/垫付工作流，经 props `selectedIds` / emit `changed` 与流水页解耦） |
| `AssetsPanel` | 资产/负债快照 CRUD + 净资产趋势图；兼管「储蓄目标」（`api/savings`，增删查，进度按起始日累计净结余实时计算） |
| `FamilyPanel` | 家庭空间（T-7.2）：创建/凭码加入/退出/解散、成员管理、月度聚合汇总、隐私互看开关；内含「家庭预算」分区（管理员设定、进度按全体成员支出汇总） |
| `LoansPanel` | 借贷台账（T-7.5）：借出/借入本金与还款跟踪，还清即结项；独立台账，不影响收支统计（在 `App.vue` 中条件挂载，见第 3 节） |
| `CategoryPanel` / `ImportPanel` / `SettingsPanel` | 分类管理；导入页外壳（组合子域组件、统一展示导入结果）；设置页外壳（组合 `settings/` 下十余张卡片） |

**子域组件**：`import/NasImportBox`（NAS 目录配置、浏览、单文件/全部导入、飞牛授权状态条）、`import/PlatformUploadGrid`（四平台上传卡片，信息单一来源 `PLATFORMS` 常量）；`settings/` 下按卡片拆分——`DatabaseCard`（数据库概览/认领/迁移向导）、`LedgerCard`（账本管理：新增/改名/删除，写操作限管理员）、`AICard`（智能分类**多供应商**设置，见下方说明）、`AutomationCard`（定时任务管理）、`NotificationCard`（逐类事件开关 + 出站 Webhook 配置与测试）、`BackupCard`、`LogsCard`、`AuditCard`（操作审计查询，管理员看全部、普通账号仅自己）、`TokenCard`（开放 API Token 签发/撤销，明文仅签发时展示一次）、`CoachCard`（AI 财务教练对话，见下方说明）、`AppearanceAboutCard`（外观三态 + **配色主题**色板 + 关于信息 + **检查更新**：进页面静默查一次、手动按钮绕后端缓存、结论按 `relation` 着色、更新说明折叠、下载 fpk/Release 详情/MD5 三个出站入口）。

**AI 智能分类设置卡（`settings/AICard`，多供应商）**：供应商下拉由后端注册表驱动（`aiConfig()` 返回的 `providers` 数组，含各供应商预置 `base_url` 与 `models`），与早期「DeepSeek 硬编码」实现不同；`onProviderChange` 在切换供应商时**回填预置地址与首个模型**，可直接改；模型字段为可手填的 `<input>` + `<datalist>`（custom 供应商可填任意模型名）；API Key 仅在表单填了新值时才随 `saveAI` 提交（后端约定不传即保留已存密钥）；`testConnection` 走 `runTask` 且 `failed: r => r.ok === false`，业务失败（HTTP 200 + `ok:false`）按错误相位处理，避免浮层绿勾配「连接失败」；`loadAI` 失败给重试入口而非永久「加载中」。

**AI 财务教练卡（`CoachCard`）**：基于结构化摘要的对话（`coachChat`），只发送聚合数据、不外传单笔流水；每条回答可展开「口径」查看喂给模型的摘要；追问保留最近 3 轮 user+coach 上下文。

> 检查更新**不出现在面板级组件里**：它是「关于应用自身」的信息，放在用户看到版本号的地方最省一次视线跳转；接口失败走内联提示而非弹窗，因为离线部署下「查不到」是常态而非异常。

**基础组件**：`AppIcon`（Feather 风格 inline SVG，path 字典，禁 emoji 图标）、`AppToast`、`AppConfirm`（Teleport + 键盘可达性）、`AppLoading`（任务 HUD）、`ThemeToggle`（auto→light→dark 循环）、`NotificationBell`（顶栏常驻通知铃铛：未读角标 + 下拉面板，60s 静默轮询未读数、`document` 点击外与 Esc 关闭，全局仅挂载一次）。

**大面板子组件拆分约定**：当单个面板内容过多（如 `DashboardPanel`、`BillsPanel`）时，按「职责内聚」拆为子组件——纯展示/自闭环逻辑的子区块（如 `HealthCard`、`ForecastSection`、`ReimbSection`）直接内嵌或用 props/emit 解耦；与面板主数据流耦合强、需要回传事件的部分（如 `ReimbSection` 接收流水页 `selectedIds`、emit `changed`）用 `defineProps`/`defineEmits` 单向数据流，禁止子组件反向改父状态。

组件规约（命名、`<script setup>` 内导入顺序、Props/Emits、设计意图注释）见 `docs/开发规范/前端开发规范.md` 第 3 节。

## 6. 状态管理（`src/store.js`）

**无 Pinia**，全局共享状态刻意只有四个（均为跨多组件复用的轻量数据）：

| 状态 | 用途 | 说明 |
| --- | --- | --- |
| `store = reactive({ tab })` | 当前标签页 | 面板切换的唯一驱动 |
| `categories = ref([])` | 全局分类列表 | 筛选栏 / 表单下拉 / 分类管理页共用 |
| `ledgers = ref(null)` | 全局账本列表（T-7.1） | 流水与看板的账本筛选、设置页账本管理共用；`null`=尚未加载、`[]`=确无账本 |
| `billsFilterHandoff = ref(null)` | 问账→流水筛选交接（T-6.2） | `QueryPanel` 写入口径，`BillsPanel` 激活时取走（读后清空），按问账口径复现筛选 |

配套 `refreshCategories()` / `refreshLedgers()`：均走 `runTask`（latest + silent），内部各自维护序号（`refreshSeq` / `ledgerSeq`）防旧响应覆盖——因为 **`latest` 模式只接管 HUD 状态、不取消在途 Promise**。只有真正跨组件的状态才进 store；组件私有状态留在组件内。

## 7. 接口层（`src/api/`）

### 7.1 请求内核 `client.js`

`api(path, options)` 统一封装四件事：

1. **运行时地址推导**：模块加载时由 `window.location.pathname` 推出 `BASE`（页面在 `/app/fn-finstat/` 下则接口同前缀，根路径部署则 `/api/*`）；导出 `apiUrl()` 供下载直链、`toQuery()`（自动跳过空值）。
2. **超时**：默认 30s；用 `AbortController + setTimeout` 把外部 signal 与超时**合并为单一 signal**——不用 `AbortSignal.timeout`（兼容旧 WebView）且不覆盖调用方 signal；超时翻译为可读文案。
3. **响应解包**：约定后端结构 `{code, msg, data}`；2xx 且 `code===0` 返回 `data`（204 返回 null），`code!==0` 抛 `Error`（附 `err.code`）。
4. **错误翻译**：非 2xx 抛 `Error`（附 `err.status` 供按状态码分支，如 403 静默降级）；非 JSON 响应（如网关登录页）对 401/403 给出专门鉴权文案。

**组件层只管 `try/catch` 后 `toast(err.message)`，不要自己判断 `res.code`；禁止直接 `fetch`。**

### 7.2 业务域文件与超时约定

各域文件（bill / stat / category / budget / asset / upload / settings / automation / notify / ai / nl_query / update / ledger / family / reimb / loans / audit / savings / forecast / tokens / coach）均为薄函数封装，**没有统一出口文件**——组件按域直接 `import`，避免多一层需要同步维护的 barrel（早先文档写的 `index.js` 统一出口在代码里并不存在，已按实际修正）。1.1.0 新增的账本/家庭/报销/借贷/审计/储蓄/预测/Token/教练等域均沿用同一薄封装形态（如 `api/ledger.js` 的 `listLedgers`/`createLedger`/`updateLedger`/`deleteLedger`、 `api/family.js` 含家庭与家庭预算、`api/reimb.js`/`api/loans.js`/`api/audit.js`/`api/savings.js`/`api/forecast.js`/`api/tokens.js`/`api/coach.js`/`api/nl_query.js`）。URL 里的 id 必须 `encodeURIComponent`。长耗时请求在调用处放大超时：上传与 NAS 导入 120s、AI 归类与数据库迁移 300s、AI 配置测试与报告生成 90s、数据库连通测试 60s、检查更新 20s（后端查发布站点上限 10s，留一倍余量而非沿用默认 30s）；下载直链（导出、日志下载、备份）走 `apiUrl()` 不经解包。其余业务读接口沿用默认 30s。

## 8. 异步任务与竞态治理（核心机制）

### 8.1 `runTask` 统一任务通道（`composables/useLoading.js`）

**禁止组件自造 `busy`/`loading` 布尔标志**，所有耗时操作（网络请求、批量任务）统一走 `runTask`：

- **防重入粒度即 key**：`isBusy(key)` 供按钮 `:disabled`；`busyMap` + 每 key 序号管理。
- **双模式**：`queue`（默认，同 key 重入直接拒绝，适合写入类）；`latest`（新请求接管同 key 旧任务——旧任务后续状态写入经 `isCurrent()` 作废，适合分页/筛选查询）。
- **HUD 任务栈**：`AppLoading` 浮层显示栈顶任务，多 key 并发互不吞浮层（先完成的任务不会提前关掉慢任务的浮层）；四态 idle/running/success/error；`update()` 汇报步骤与进度；`silent: true` 只做防重入不弹浮层。
- **不会卡死**：所有路径（含异常、主动放弃 `TASK_CANCELLED`）最终在 `finally` 解锁；失败卡片停留 8s 可手动关闭。
- 失败时 HUD 显示错误并**原样抛出**（`rethrow` 默认 true），业务侧 `try/catch` 语义不变。

### 8.2 旧响应不得覆盖新响应（双保险）

`latest` 不取消在途 Promise，凡 `await` 之后要写响应式数据的地方，必须自判「是否最新」：

```js
let loadSeq = 0;
async function load() {
  const seq = ++loadSeq;
  const res = await listBills(params);
  if (seq !== loadSeq) return;          // 已有更新请求，丢弃本次结果
  bills.value = res.items;
}
```

用 `runTask` 时等价写法为 `if (!isCurrent()) return null;`。快速切换筛选/翻页时不做此判定会出现旧数据覆盖新数据——这是本项目明确治理过的问题（见 `docs/devlog/2026-09-13-全局任务进度Loading统一改造.md`）。

### 8.3 两个收口期沉淀的不变量

1. **`rethrow:false` 的失败态必须显式处理**：当 `runTask` 带 `rethrow:false` 时，任务失败不再抛错，而是 **resolve 为 `undefined`**。因此调用方不能在之后假定「拿到结果即成功」，而必须判断返回值（如 `if (res === undefined) loadFailed.value = true`）或单独捕获——`FamilyPanel`/`LoansPanel`/`TokenCard` 等都据此把「加载中…」翻转为「重试」入口，避免首屏失败后面板永久空白或浮层卡死。这是一个跨多面板复用的收口约定。
2. **时间窗口一律用本地时区，禁止 `toISOString()` 的 UTC 日期**：凡是「月」或「日」的选择（如 `FamilyPanel` 的 `month`、预算区的 `currentMonth()`）都来自 `utils/datetime.js` 的 `currentMonth()`（按运行环境本地时区取 `YYYY-MM`），严禁用 `new Date().toISOString().slice(0,10)`——后者在 UTC+8 且本地已过午夜时会偏成前一天，导致跨时区部署下统计窗口错位。该约定由 `FamilyPanel` 的注释显式钉住，新增涉及时间切片的逻辑须复用 `datetime.js` 而非自拼 UTC 串。

## 9. 用户反馈体系

**禁用原生 `alert` / `confirm`**，三件套均已在 `App.vue` 挂载一次，新组件不得重复挂载：

| 场景 | 机制 |
| --- | --- |
| 耗时任务进度 | `runTask` → `<AppLoading />` HUD（无遮罩不阻塞，确定进度走进度条、不确定走循环动画） |
| 轻提示 | `toast("已保存")` / `toast(err.message, true)`（错误样式），2.6s 自动消失 |
| 二次确认 | `if (!(await confirm({ title, message, danger: true }))) return;`（新弹窗打开时旧未决 Promise 按取消 settle，防悬挂） |

失败反馈必须说清原因（透传 `err.message`），不允许笼统的「操作失败」。

## 10. 主题系统

### 10.1 两套正交的维度（`theme.js`）

主题由两个**正交**维度组成，彼此独立、可任意组合：

- **明暗模式 `themeMode`**：三态 auto（默认）/ light / dark，持久化于 localStorage（`THEME_KEY = "fn-finstat-theme"`）。暗色判定优先级：**用户显式选择 > 飞牛宿主主题 > 系统 `prefers-color-scheme`**。
- **配色主题 `themeAccent`**：七套可切换配色（见 10.4），持久化于 localStorage（`ACCENT_KEY = "fn-finstat-accent"`），默认 `pine`。

两者各自有独立的 `watchEffect` 同步到 DOM，互不依赖：`themeMode` 改写 `html.classList.toggle("dark")` + `<meta name="theme-color">`；`themeAccent` 改写 `html` 的 `data-theme` 属性（`pine` 时移除属性走默认令牌，其余设 `data-theme="x"`）。**明暗切换 = 只切 `html.dark` 一个类，组件零改动；配色切换 = 只切 `data-theme`，且只覆盖品牌/中性令牌层，收支语义层不动（见 10.4）**。另监听 `window` 的 `storage` 事件，使多标签页间明暗与配色都实时同步。

auto 态另有后端兜底通道：请求 `/api/settings/about` 取 `fnos_theme`（跨域 iframe 场景下前端探测可能全部失效时的可靠来源）。`followingFnos` 状态标记当前是否真的跟随上了飞牛宿主，供设置页提示（避免用户误以为没生效）。

> 切换入口常驻：明暗三态由 `ThemeToggle`（侧边栏底部 / 移动端顶栏）循环切换；配色主题由设置页「外观」的色板圆点（`AppearanceAboutCard` 用 `ACCENTS` + `setAccent`）选择。

### 10.2 飞牛主题多源探测降级链（`fnos.js`）

iframe 内嵌 + 可能跨域，宿主主题按以下优先级探测，全部失败落到系统偏好：

```
0 官方 SDK（getPlatformConfig + $on('os/theme')，动态 import、仅 iframe、2.5s 超时竞速）
1 URL 参数（fnos-theme / theme / colorScheme）
2 同源 localStorage（fnos-theme-mode，读自己与父窗口）
3 隐藏探针元素回读宿主背景色亮度（luma < 110 判暗）
4 postMessage（仅接受 event.source === window.parent，防伪造）
5 后端透传（/api/settings/about，由 theme.js 触发）
6 系统 matchMedia 兜底
```

SDK 推送的值标记为权威（`sdkControlled`），不被次级通道覆盖。实时性靠 storage/message/focus 等事件 + 可见时 4s 轮询。

### 10.3 首屏防白闪（`index.html`）

`<head>` 内联 IIFE 在 Vue 加载前**同步**判定暗色并给 `html` 加 `dark` 类；**同时恢复配色主题**——读取 `localStorage` 的 `fn-finstat-accent`，命中 `ocean/violet/rose/coffee/slate/aurora` 之一即给 `html` 设 `data-theme`，`pine`/缺省则不设（与运行时 `theme.js` 的 `ACCENTS` 取值列表保持一致）。优先级与运行时一致（显式选择 > 同源 localStorage / URL 参数 / 父窗口 matchMedia > 系统）。首屏刻意不用 SDK——异步握手赶不上首屏且可能永久挂起。favicon 双主题 + `theme-color` meta 同步预挂（带 `media` 的两个 `<link>` 覆盖支持该属性的浏览器，脚本再补一份无 `media` 的最高优先级兜底，以飞牛主题为准）。

### 10.4 配色主题体系（`assets/styles/themes.css`）

`themeAccent` 在 `theme.js` 的 `ACCENTS` 中定义为七套：`pine`（松烟，默认，即 `tokens.css` 本身，无 `data-theme`）、`ocean`（沧蓝）、`violet`（紫棠）、`rose`（绯樱）、`coffee`（焦糖）、`slate`（石墨）、`aurora`（极光）。其中 1.1.0 **新增六套可切换配色**（沧蓝/紫棠/绯樱/焦糖/石墨 + 极光科技感皮肤），每套自带日间 + 夜间两套。

- **正交组合**：每套配色在 `themes.css` 中各用两段选择器成对维护——`html[data-theme="x"]:not(.dark)`（日间）与 `html[data-theme="x"].dark`（夜间）；夜间套特异性高于基础 `html.dark`，能整体接管。
- **只覆盖品牌与中性层**：每套仅重定义 `--color-primary` / `--color-primary-hover` / `--color-primary-soft` / `--color-on-primary` / `--color-accent` / `--color-bg*` / `--color-surface*` / `--color-border*` / `--color-sidebar-bg` / `--color-input-focus` / `--chart-splitline` 等；**收支语义（`--color-income` / `--color-expense` / `--color-warn` / `--color-danger` / `--color-success`）与文字墨色全局共享、不随配色变化**，保证所有主题下数字口径与可读性一致。
- **极光（aurora）的科技感细节层**：仅在夜间额外追加 HUD 细节——`body` 的 34px 方格青色网格背景、`.btn.primary` 与 `.nav-item.is-active` 的霓虹辉光（透明度压到 0.15~0.3），日间保持冰蓝干净专业；霓虹色仅作低透明度点缀，正文可读性令牌不受影响。
- 组件内若需强调色（如进度条填充）统一用 `var(--accent, #e8833a)` 回退到当前配色的 `--color-accent`，实现「随配色自适应」而不硬编码。

| 能力 | 实现 |
| --- | --- |
| 主题 | `fnos.js`（第 10.2 节） |
| 目录授权 | `fnosAuth.js`：SDK `trim.file` 的 `userAccess`（个人目录 `pickUserFile`）与 `sharedAccess`（管理员共享目录 `pickSharedFile`）两条链路；动态 import + 10s 超时 + 仅 iframe + 仅用户点击触发 |
| 身份 | 前端**不直接获取**用户身份：后端经网关头解析，授权状态以 `/api/nas/authorization` 为权威来源；前端 `checkPathsAcl` 仅作体验级二次校验（失败放行，真正防线在后端 `_resolve_in_root` 与 ACL） |

SDK 使用的统一守卫模式：**动态 import**（SDK 包顶层访问 `window`/`navigator`，不可静态引入）、**超时竞速**（无响应宿主会永久挂起）、**失败静默降级**（独立访问形态下功能退化为隐藏入口而非报错）。

## 12. 图表体系

- **生命周期统一走 `useChart`**（`composables/useChart.js`）：容器可见性校验、`ResizeObserver` 自适应、卸载 dispose、`watch(isDark)` 主题重绘、`canRender()` 前置条件（面板 `display:none` 时跳过重绘防 0 尺寸画面）。**不要手写 init/resize/dispose 样板**。
- **按需注册**：`utils/charts.js` 只注册用到的渲染器与组件（Line/Pie/Bar/Heatmap/Scatter + Grid/Tooltip/Legend/VisualMap/Calendar + CanvasRenderer）；刻意不注册 GeoComponent。
- **配色走 `utils/chartTheme.js`**：画布读不到 CSS 变量，故从 `:root` 计算样式读设计令牌（`chartTokens()`，带暗色回退值）；分类色板明暗两套；热力色阶随主题反转深浅方向。主题切换时各图表用缓存数据免请求重绘。
- ECharts 整库独立 chunk，**不要整包 import 到主包**（见第 14 节）。

## 13. 设计令牌（`assets/style.css` + `assets/styles/`）

样式按主题域拆到 `assets/styles/` 后，`assets/style.css` 仅作为**聚合入口**被 `main.js` 引用，按级联顺序 `@import` 七个子文件：`tokens.css` → `themes.css` → `base.css` → `layout.css` → `components.css` → `pages.css` → `responsive.css`（`themes.css` 须紧跟 `tokens.css`：主题块要整体接管基础令牌又不能压过组件层）。

四层令牌体系（完整定义见 `docs/界面设计方案.md`）现在落在 `tokens.css`：

| 层 | 内容 | 组件可用性 |
| --- | --- | --- |
| 1 基础调色板 | `--pine-*`（墨绿主色）/ `--paper-*`（暖米白）/ `--ink-*` / `--brass-*` / `--clay-*` / `--moss-*` 等 | ❌ 禁用 |
| 2+3 语义映射 | 浅色（`:root`）与深色（`html.dark`）两段 `--color-*` / `--chart-*`；`tokens.css` 同时定义 `--color-accent` 默认（brass） | ✅ **组件只用 `--color-*` 层** |
| 4 尺度 | `--space-*`（4px 基准）/ `--radius-*` / `--shadow-*` / `--z-*` / `--dur-*` / `--ease-*` | ✅ |

配色主题层（第 10.4 节）由 `themes.css` 承载——它只覆盖各 `data-theme` 下的品牌/中性令牌，不重复定义收支语义与尺度层，从而保证「换配色不改数字口径」。

**硬性禁止**：硬编码颜色、裸 `z-index`（用 `--z-modal` / `--z-toast` / `--z-hud` 等）、裸 px 间距/圆角、组件内重写主题配色。

**收支色彩约定（以代码实现为准）**：`--color-income` = 暖红系（clay）、`--color-expense` = 墨绿系（moss），即**收入用红、支出用绿**的国内记账直觉；与主色 `--color-primary`（墨绿 Pine）区分。金额展示统一用 `utils/format.js` 的 `fmtSignedMoney` / `amountClass`，不自拼正负号与颜色类。

## 14. 构建与产物

### 14.1 Vite 配置（`vite.config.js`）

- `base: "./"`（前缀运行时可变）+ `outDir: "../app/static"`（项目根之外，显式 `emptyOutDir: true`）。
- **函数式 `manualChunks`**：`/node_modules/echarts/` 整库拆独立 chunk（约 628KB，升级频率低利于长缓存；主包约 183KB）；`chunkSizeWarningLimit: 700`，新增大依赖需评估拆分。
- 自定义插件 `bumpSwVersion`：`closeBundle` 阶段把 `app/static/sw.js` 的 `SW_VERSION` 改写为构建时间戳——历史上依赖手工递增、漏改导致旧资源缓存永久堆积；改写失败仅告警不阻断。**不要手工改 `SW_VERSION`**。
- dev server 5173，`/api` 与 `/app/fn-finstat` 代理到本地后端 8090。

### 14.2 Service Worker 缓存策略（`public/sw.js`）

仅生产构建注册（`import.meta.env.PROD`），相对路径 `./sw.js` 注册使其作用于部署前缀之下。拦截仅同源 GET：

| 请求 | 策略 |
| --- | --- |
| `/api/*` | 一律直连不缓存 |
| `/assets/*`（内容哈希文件名） | **缓存优先** |
| 其余（页面导航等） | **网络优先**，失败或 5xx 回退缓存（后端重启也能打开上次页面） |

`install` 即 skipWaiting；`activate` 清理非当前版本缓存并 `clients.claim`。版本隔离靠构建盖章的 `SW_VERSION`。

### 14.3 产物归属（硬约定）

`app/static/` **整目录**是 vite 构建产物，**没有任何文件入库**（`.gitignore` 排除整目录）：

| 路径 | 构建输入 | 入库 |
| --- | --- | --- |
| `app/static/index.html` | `frontend/index.html`（构建注入 assets 引用后写出） | ❌ 禁止入库 |
| `app/static/sw.js` | `frontend/public/sw.js`（再被插件盖章 `SW_VERSION`） | ❌ 禁止入库 |
| `app/static/manifest.webmanifest` | `frontend/public/manifest.webmanifest` | ❌ 禁止入库 |
| `app/static/icons/*.png` | `frontend/public/icons/*.png` | ❌ 禁止入库 |
| `app/static/assets/` | 内容哈希命名的 js/css | ❌ 禁止入库 |

依据：`vite.config.js` 的 `outDir` 是 `../app/static` 且 `emptyOutDir: true`——**每次构建都会先清空整个目录再重写**，目录里不存在"输入模板"。把其中任何文件入库，都会在下一次 `npm run build` 时被删掉重写并在工作区留下持续 dirty（`sw.js` 的时间戳每次都变）。

两条配套约束：

- **不要加 `app/static/.gitkeep`**：`emptyOutDir` 会把它一起删掉，反而制造永久 dirty。目录缺失由 `app/main.py` 的 `(STATIC_DIR / "assets").mkdir(parents=True, exist_ok=True)` 兜底（连带创建 `static/`），保证 `import app.main` 不崩。
- **PWA 根路由要能容忍文件缺失**：`_serve_sw` / `_serve_manifest` 在文件不存在时返回 404 而非 500（未构建前端时不应污染日志）。

`app/static` 缺失或 `assets/` 为空时打包会产出白屏 FPK——打包前有静态产物门禁兜底（先查 `index.html` 再查 `assets/`），详见 `docs/开发规范/编译与构建规范.md`。

## 17. 典型数据流

**账单列表加载**：点击侧边栏 → `store.tab='bills'` → CSS 显示 `BillsPanel` → 其 `watch(tab)` 触发 `load()` → `runTask({key:'bills:load', mode:'latest'})` 包裹 `listBills(params)`（api/bill.js → client.js）→ 自维护 `loadSeq` 校验后写响应式状态 → 表格渲染；快速翻页旧响应作废。删除/批量走 `confirm()` → `runTask`（queue 防重入）→ 页码回退 → 重新 `load()`。

**导入账单**：上传路径 `PlatformUploadGrid` 按 `PLATFORMS` 常量渲染四卡片 → `runTask({key:'upload:<platform>'})` 包裹 `uploadBillFile`（FormData，120s）；NAS 路径 `NasImportBox` 先经 `fnosAuth` 唤起 SDK 授权 → 保存目录 → 浏览/导入（逐文件汇报进度）。两路 emit 统一由 `ImportPanel` 展示结果（解析/新增/重复跳过/失败 + AI 归类计数 + 异常明细导出 CSV）。

**统计看板**：`DashboardPanel` 激活 → 单个 `runTask` 内 `Promise.all` 并发 4 个统计接口并逐个汇报进度 → `isCurrent()` 校验 → `nextTick` 后经 `useChart` 渲染（配色取 `chartTheme`）；子区块各自独立懒加载；主题切换时图表用缓存数据重绘。

**检查更新**：`SettingsPanel` 挂载 `AppearanceAboutCard` → `onMounted` 里以 `runTask({key:'update:check', silent:true, rethrow:false})` **静默**查一次（同页面的 `about:load` 同为静默轻请求）→ `checkUpdate(false)`，后端命中 5 分钟缓存时立即返回 → 结果写 `updateResult` 渲染结论行。用户点「重新检查」走同一 key 但 `manual=true`：显示进度浮层、传 `refresh=true` 绕过后端缓存。**离线时不抛错**（后端回 `ok=false`），故 `failed: r => r.ok === false` 把它判为错误相位，避免浮层弹绿勾却写着「无法连接更新服务器」。

**对话式查账（问账）**：`QueryPanel` 输入问题 → `runTask({key:'query:ask'})` 包裹 `askQuestion(q, history)`（api/nl_query.js，回传最近 3 轮 `{question, spec}` 作为追问上下文）→ 渲染回答卡（结论 + 分组占比条 + 「依据」折叠区，口径随每条答案展示）；点「存为筛选」把 `spec` 的时间/收支类型/分类/商户写入 `store.billsFilterHandoff` 并切到 `bills` 标签，`BillsPanel` 激活时取走该交接对象复现筛选（读后清空）。

**家庭空间加载**：进入 `family` 标签（或 `FamilyPanel` 的 `watch(tab)` 首次命中）→ `runTask({key:'family:load', mode:'latest', rethrow:false})` 包裹 `getFamily()`；命中家庭后再并发 `familySummary(month)` 与 `familyBudgetOverview(month)`（各自维护 `summarySeq`/`budgetSeq` 防切月竞态）。`rethrow:false` 时若返回 `undefined` 即置 `loadFailed` 给重试入口，避免首屏失败永久空白（同约定见 8.3）。

**借贷台账**：`LoansPanel` 因 `v-if` 仅在激活后挂载 → `onMounted` 触发 `runTask({key:'loans:load', mode:'latest', silent:true, rethrow:false})` 包裹 `loanLedger()`；展开某条借款的还款明细时再懒加载 `loanPayments(id)`（latest + silent）。还款登记后乐观回读进度，若 `status==='settled'` 提示「已还清，自动结项」。

**通知中心轮询**：`NotificationBell` 在 `onMounted` 以 `runTask({key:'notify:badge', silent:true, rethrow:false, mode:'latest'})` 拉未读数，并 `setInterval(refreshBadge, 60_000)` 静默轮询；页面可见性恢复（`visibilitychange`）与打开下拉面板时立即刷新；角标 `>99` 显示「99+」。
