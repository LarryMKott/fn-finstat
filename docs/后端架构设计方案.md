## 1. 系统概述与部署形态

fn-finstat 后端是一个**单进程 FastAPI 单体应用**，作为飞牛 fnOS 的微应用（`manifest` 声明 `micro_app=true`）运行在 NAS 设备上，提供账单导入、流水管理、统计分析、预算、资产快照、AI 报告等能力。有两种部署形态：

| 形态 | 监听方式 | 身份来源 | 安全前提 |
| --- | --- | --- | --- |
| **fnOS 网关模式**（默认） | `uvicorn --uds` 只绑 Unix Socket `app.sock`，不占 TCP 端口 | fnOS 统一网关注入 `X-Trim-*` 请求头 | 网关完成登录校验；应用不直接暴露网络 |
| **独立部署 / 本地开发** | TCP，`config.HOST` 默认 `127.0.0.1`、`PORT` 默认 `8090` | 无身份头 = 单机唯一用户，全量放行 | 只允许本机访问 |

> ⚠️ **信任边界**：`X-Trim-Userid / X-Trim-Username / X-Trim-Isadmin` 三个请求头**只在受保护的传输面上生效**（fnOS 网关模式绑 Unix Socket 且缺失身份头 401；独立部署绑 `127.0.0.1` 并叠加来源校验中间件，详见下文与第 6 节）。整个权限体系的安全性由「应用不可被不可信网络直接访问」保证（`app/api/deps.py` docstring 明确记载）。任何改变监听地址、增加反向代理、暴露端口的改动都必须重新评估此前提。
>
> 两种形态下的空身份处理不同（评审报告 H-1 收紧项）：
> - **fnOS 网关模式**：缺失身份头一律 **401 / code=10006**（`请通过飞牛桌面访问本应用`），覆盖包括普通接口在内的全部路径——数据隔离依赖 `user_id` 过滤，匿名写入会落在不存在的账号上。设备上经 `curl --unix-socket` 排障时可临时设环境变量 `FNOS_ALLOW_HEADERLESS=1` 恢复旧行为（启动日志会警示）。
> - **独立部署**：空身份 = 单机唯一用户放行；同时启用来源校验中间件（见第 6 节 `SourceGuardMiddleware`），`HOST` 改为非回环地址时启动日志告警信任面扩大。

## 2. 总体架构与分层

```
浏览器 → fnOS 统一网关（登录校验、注入 X-Trim-* 头）
       → uvicorn（Unix Socket）→ 中间件链 → FastAPI 路由
                                              │
   main ── api（路由编排）                      │
           │                                   │
           ├── services（业务逻辑）             │
           │      └── db/dao（数据访问）        │
           │             └── db/engine（三方言）┘
           ├── parsers（账单解析）
           ├── utils（纯函数）
           └── core（横切：错误码/上下文/权限/中间件/异常适配）
```

**依赖方向（单向，禁止反向）**：

```
core ← utils ← parsers ← db(dao) ← services ← api ← main
```

| 层 | 目录 | 职责 | 禁止 |
| --- | --- | --- | --- |
| core | `app/core/` | 错误码、异常族、请求上下文、权限中间件、观测/安全中间件、异常→HTTP 适配 | 依赖任何业务层 |
| utils | `app/utils/` | 纯函数（金额、周期、筛选、文件头、分类关键词、地区推断） | 运行期依赖 Web 框架、写库 |
| parsers | `app/parsers/` | 四平台账单文件解析，注册表 `PARSERS` 单一来源 | 反向依赖 services |
| db | `app/db/` | 引擎/迁移/ORM/DAO；DAO 静态方法 + `user_id` 隔离 | 依赖 services / api |
| services | `app/services/` | 业务校验与流程编排，异常语义化 | 抛 `HTTPException`、import fastapi |
| api | `app/api/` | 参数校验、依赖注入、`ok()` 包装 | 业务逻辑、直接写库 |

**铁律**：`db` / `utils` / `parsers` / `services` 运行期不得 import fastapi（唯一例外：`app/utils/file_utils.py` 的 `UploadFile` 仅作 `TYPE_CHECKING` 标注）。

## 3. 技术选型

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | FastAPI + Uvicorn | 端点以**同步 `def`** 为主（SQLAlchemy 同步 ORM），仅确需 `await` 处用 `async def` |
| ORM | SQLAlchemy 2.x 声明式 | 单代码库适配三种数据库 |
| 数据库 | SQLite（默认）/ MySQL / PostgreSQL | 差异统一封装在 `app/db/engine.py`，业务代码不感知方言 |
| 校验 | Pydantic v2 | `app/schemas/` 按业务域组织 |
| AI 调用 | 标准库 `urllib` | 不引入重型 HTTP 客户端；禁跟随重定向防 Key 外泄 |
| 日志 | logging + RotatingFileHandler | 单文件 10MB、保留 3 份 |
| 质量 | pytest + ruff（F,E9）+ black（line-length 88） | 均接入 CI 门禁 |

## 4. 应用启动与生命周期（`app/main.py`）

**导入期**：

1. `_setup_logging()`：为 root 与 uvicorn 系 logger 挂 `RotatingFileHandler`；按「目标 logger 是否已挂同路径 handler」防重入（不能只靠模块级标志，`uvicorn --reload` 会重新执行模块导致日志翻倍）。日志路径 fnOS 下由 `cmd/main` 注入 `LOG_FILE`。
2. 创建 `app/static/assets` 空目录兜底——该目录是 gitignore 的前端构建产物，全新 clone 缺失时保证应用可导入。

**应用装配**：`FastAPI(title="财务统计", version=APP_VERSION, lifespan=...)` → `register_exception_handlers(app)`（`app/core/handlers.py`）→ `add_app_middlewares(app)`（`app/core/middleware.py`）。

**双前缀路由注册（`_prefixes` 机制）**：`_prefixes = ["", API_BASE_PATH]`（默认前缀 `/app/fn-finstat`，可由向导参数改）。对每个前缀循环挂载：

- 10 个业务 router：upload / nas / bill / budget / asset / category / stat / settings / automation / ai（前缀定义在各自文件的 `APIRouter(prefix=...)`）；
- `{prefix}/static` 普通静态挂载；`{prefix}/assets` 用 `ImmutableStaticFiles` 加 `Cache-Control: immutable, max-age=31536000`（内容哈希文件名可永久缓存）；
- PWA 显式路由：`/sw.js`、`/manifest.webmanifest`、`/icons/{name}`。

新建 router 后**必须在两个前缀下都注册**，漏挂会导致自定义前缀下 404。首页 `GET /` 返回 `index.html`（no-cache）；前缀模式下 `GET {PREFIX}` 302 到 `{PREFIX}/` 保证相对路径解析。

**lifespan**：`init_db()`（建表 + 迁移 + 预置默认分类）→ `CategoryDAO.repair_orphans()` → 注册内置任务 `nas_watch`（NAS 目录监听导入，间隔 30 分钟）→ `scheduler.ensure_builtin_tasks()` 并按开关启动进程内 asyncio 调度循环；关闭时 `stop_loop()`。

## 5. 请求生命周期（端到端）

```
① 浏览器 https://<nas>/app/fn-finstat/api/...
② fnOS 网关：登录校验，注入 X-Trim-Userid/Username/Isadmin（及主题头），保留前缀转发
③ uvicorn --uds app.sock 接收，进入 ASGI 栈
④ 中间件链（外→内）：观测 → 安全头 → 权限门禁 → GZip
⑤ 路由匹配（双前缀）；router 级依赖 request_db_session 创建请求级 DB 会话
⑥ 身份依赖 CurrentUser/AdminUser 解析网关头；Pydantic 校验请求体
⑦ 服务层：业务校验、字段归一化、互斥锁、副作用（AI/NAS/调度）
⑧ DAO 层：get_db() 复用请求会话；「预检查 + 唯一约束兜底」；三方言差异经 engine.py 抹平
⑨ 响应：ok() 包装 {code,msg,data}；异常经 handlers 翻译；回程再经压缩/安全头/观测头输出
```

## 6. 中间件链

三个自定义中间件**全部为纯 ASGI 实现**（非 BaseHTTPMiddleware，避免其缓冲与后台任务问题），注册顺序与实际洋葱顺序（外→内）：

| 顺序 | 中间件 | 职责 |
| --- | --- | --- |
| 最外 | `ObservabilityMiddleware` | 请求 ID（信任上游 `X-Request-ID` 但按 `[0-9a-zA-Z_-]{1,64}` 防注入，否则生成 uuid 前 16 位）写入 ContextVar 与 scope；响应头 `X-Request-ID` / `X-Process-Time-Ms`；慢请求（≥1s）记 INFO、5xx 记 WARNING |
| 2 | `SecurityHeadersMiddleware` | `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`；**刻意不加 frame 类头**——应用被 fnOS 桌面 iframe 内嵌 |
| 3 | `SourceGuardMiddleware` | **仅独立部署生效**（fnOS 模式整体跳过）：① Host 白名单（全部请求）——Host 不在 `config.ALLOWED_HOSTS`（回环集合 ∪ 具体绑定的 HOST）即 403，防 DNS rebinding；`HOST` 为通配地址（`0.0.0.0`）时无法枚举局域网访问名，白名单关闭；② 写方法（POST/PUT/DELETE/PATCH）Origin 同源校验——Origin 缺失（curl/脚本/SW）放行、非同源 403，防跨站 CSRF。被拦请求回统一响应体（code=10002） |
| 4 | `PermissionMiddleware` | 集中式身份认证 + 权限门禁，见第 8 节 |
| 最内 | `GZipMiddleware` | minimum_size=1024 |

兜底 500 由 FastAPI 默认 `ServerErrorMiddleware` 承担；因该层在自定义中间件之外（响应不再经过中间件），兜底处理器需**自行补写安全头与从 scope 读取请求 ID**。

## 7. 接口契约与错误处理

### 7.1 统一响应结构

除文件下载端点（导出 xlsx/csv、备份 JSON、日志）外，所有接口返回：

```jsonc
{ "code": 0, "msg": "ok", "data": <业务数据> }            // 成功 2xx
{ "code": 40002, "msg": "交易单号已存在", "data": null }   // 失败，data 恒为 null
```

路由声明 `response_model=ApiResponse[...]`，返回用 `ok()` 包装（定义在 `app/schemas/common.py`，含 `PageResult[T]`）。

### 7.2 错误码分段（`app/core/errors.py::ErrorCode`）

| 段 | 领域 |
| --- | --- |
| 0 / 100xx | 成功 / 通用（参数、权限、不存在、冲突、上传限制） |
| 400xx / 410xx / 420xx / 430xx | 账单 / 分类 / 导入解析 / NAS |
| 440xx / 450xx / 470xx / 480xx | 预算 / 资产快照 / 设置与数据库 / AI |
| 50000 | 服务器内部错误 |

新增领域**新开号段**，不复用其他领域的段。

### 7.3 异常协议

服务层与 DAO 层只抛 `BizError` 子类，**路由层不写 try/except 翻译**，由全局异常处理器统一转换：

| 异常 | HTTP | 用途 |
| --- | --- | --- |
| `ValidationError` / `PermissionDeniedError` / `NotFoundError` | 400 / 403 / 404 | 参数与业务规则 / 权限 / 不存在 |
| `ConflictError` / `UploadTooLargeError` / `ImportParseError` / `ConfigError` | 400 | 唯一冲突（刻意不用 409）/ 上传超限 / 文件内容问题 / 配置错误（message 含操作指引） |
| `EnvironmentError_` | 500 | 运行环境故障（驱动缺失等） |

`ImportParseError`（用户文件问题）与 `EnvironmentError_`（环境故障）必须区分——把环境故障伪装成输入错误，用户会反复改文件却永远修不好。`msg` 面向用户、可被前端 `toast` 直接展示；禁止堆栈、SQLAlchemy 细节、绝对路径入 `msg`。全局处理器覆盖四类：`BizError`、`RequestValidationError`（保持 422 但 body 换统一结构）、`StarletteHTTPException`（覆盖未匹配路由 404）、兜底 `Exception`（500 通用文案 + `logger.exception` 记完整堆栈）。

## 8. 身份与权限

### 8.1 身份解析（唯一入口）

`app/core/context.py::gateway_user_from_headers` 统一解析 `X-Trim-*` 头为 frozen dataclass `GatewayUser`（`user_id/user_name/is_admin/theme_raw`），api/deps 与权限中间件共用；管理员判定只认 `X-Trim-Isadmin: true`。`request_id_var` ContextVar 承载请求 ID 供日志关联。

### 8.2 依赖注入（`app/api/deps.py`）

- `CurrentUser` / `AdminUser` 为 `Annotated` 签名别名，替代重复的 `Depends(...)`；
- `request_db_session` 为 **async 生成器**：FastAPI 对同步依赖在线程池副本中执行，副本里 set 的 ContextVar 不回传请求任务——会话经 `bind_request_session()` 绑入 `app/db/engine.py` 的 ContextVar，DAO 侧 `get_db()` 才能复用同一会话；事务边界仍由各 `get_db()` 块自行提交/回滚。

### 8.3 双层权限防御

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 第一层 | `core/permissions.py::PermissionMiddleware` | 路由分发前两级判定（`access_rejection()`）：fnOS 模式缺失身份头 → 401（code=10006）；管理面非管理员 → 403（code=10002）。策略表 `_ADMIN_RULES`（`(HTTP 方法集合, 路径正则)`）枚举全部管理面，先 `strip_api_prefix` 再匹配，**默认拒绝管理面**，漏挂路由守卫也兜底 |
| 第二层 | `deps.require_admin` / `AdminUser` | 路由守卫，提供 OpenAPI 语义的 401/403 |

新增管理员接口**必须两处同步更新、文案一致（同指 `ADMIN_ONLY_MSG` / `UNAUTHENTICATED_MSG`），并补测试**。独立部署下无身份头（`user_id` 为空串）= 本地单机唯一用户全量放行——该规则的安全前提即第 1 节的网络隔离与来源校验中间件。

### 8.4 数据隔离

普通接口的数据隔离由**服务层按 `user_id` 过滤**保证，不依赖权限中间件；所有 DAO 查询条件必须带 `user_id`。

## 9. 数据层设计（`app/db/`）

### 9.1 三方言引擎（`engine.py`）

- `engine_url()` 按 db_type 构造 `mysql+pymysql`（utf8mb4）/ `postgresql+psycopg2` / sqlite URL；驱动缺失时懒检查并抛带安装指引的错误（`drivers.ensure_driver` 可用当前解释器 `pip install`，供设置页不重启切库）。
- SQLite 连接挂 connect 事件设 `PRAGMA journal_mode=WAL / foreign_keys=ON / busy_timeout=5000`；外部库用 `pool_size=5, max_overflow=5, pool_pre_ping, pool_recycle=1800`。
- `_EngineState` 线程安全持有当前引擎与会话工厂，`activate()` 整体替换，支持**运行期切库**。
- 三方言差异工具：`insert_ignore_rows()`（MySQL `INSERT IGNORE` / PG `on_conflict_do_nothing` / SQLite `OR IGNORE`）、`in_chunks(size=900)`（IN 子句切片，规避 SQLite 绑定变量上限）、`translate_unique_violation()` / `is_unique_violation()`（按驱动文案判定唯一冲突并转 `ConflictError`）。
- **不用驱动的 `rowcount` 判断插入条数**（SQLite/PG 可能返回 -1），用事务内 `COUNT` 差值。

### 9.2 会话管理

业务代码统一 `with get_db() as session:`（正常提交、异常回滚），不自建 sessionmaker；请求内经 ContextVar 复用 `request_db_session` 注入的同一会话，后台线程（调度、AI 批处理）每次新建。

### 9.3 数据模型（`models.py`，9 张核心表）

| 表 | 要点 |
| --- | --- |
| `bills` | `user_id` 归属、`tx_id` 全局唯一、tags/reimbursed、`deleted` 软删除（回收站） |
| `categories` | name 唯一；`DEFAULT_CATEGORIES` 预置 |
| `budgets` | user_id + month + category 唯一 |
| `asset_snapshots` | 资产/负债快照 |
| `app_meta` | 键值元数据（schema 版本戳） |
| `scheduled_tasks` / `task_runs` | 定时任务定义（含 `running_at` 软锁、`locked_by/locked_until` 多实例预留）与运行历史 |
| `imported_files` | `path_key=sha256(path)` 唯一 + `content_hash` 指纹判重 |
| `ai_reports` | user_id + period_type + period_value 唯一 upsert |

### 9.4 Schema 迁移（`migrations.py` + `base.py`）

- 迁移函数登记在 `_MIGRATIONS`（`vN → vN+1`），当前 `BASELINE_SCHEMA_VERSION=1`、`LATEST_SCHEMA_VERSION=5`。
- **每个迁移必须幂等**（MySQL DDL 隐式提交、无法回滚，中断重启会重跑）；独立事务、完成后立即写版本戳，支持断点续迁；跨方言加列用 `_add_column_if_missing`（PG `IF NOT EXISTS`，MySQL/SQLite 先查信息架构）。
- `init_db()` 流程：读生效配置 → SQLite 待迁移时先 checkpoint 并备份 `bill.db.bak-v{N}` → `create_all` → 版本判定（老库按基线补记）→ 逐版本迁移 → 检测 `db_meta.json` 类型变更则从旧 SQLite 搬数据 → 空分类表预置默认分类。
- 跨库搬移在 `copy.py`：目标空则保 id 整搬（PG 用 `setval` 同步序列），非空按唯一键去重合并（含无 tx_id 流水的业务键，防重复翻倍）。

### 9.5 DAO 规约（`app/db/dao/`）

清单：`bill_dao`（含回收站、`existing_tx_ids` 去重预查）、`category_dao`（含 `repair_orphans`）、`budget_dao`、`asset_dao`、`stat_dao`（月分组统一 `substr(tx_time,1,7)` 保证三方言一致）、`task_dao`（含 `TaskLock` 软锁句柄与 `ImportedFileDAO`）、`ai_report_dao`。

统一写法：`class XxxDAO` + `@staticmethod`，不实例化；查询必带 `user_id`；返回 dict（`as_dict()`）不泄漏 ORM 对象；排序字段经**白名单映射**到模型列；列表接口导出分页上限常量（如 `EXPORT_LIMIT=100_000`）。

## 10. 关键子系统设计

### 10.1 账单导入管线（`services/import_service.py`）

```
上传/NAS 文件 → detect_source 识别平台 → build_parser 解析为标准字段
→ _parse_and_normalize（5 万条上限 → 列宽截断 → 关键词归类 → AI 二次归类）
→ _split_fresh_and_dups（existing_tx_ids 预查 + 批内去重，产出差异明细）
→ CategoryDAO.ensure_many 自动建分类 → BillDAO.insert_many（预查 + 唯一约束双保险）
→ ImportResult(total/inserted/skipped_dup/ai_classified/details) → 可导出差异 CSV
```

- 导入与备份恢复共用 `RESTORE_LOCK` 互斥（见第 11 节）。
- 解析异常按「文件内容问题（`ImportParseError`）/ 环境故障（`EnvironmentError_`）」分流，不互相伪装。
- AI 二次归类只处理关键词未命中的流水，失败或超预算（90s）**不阻断导入**。

### 10.2 账单解析器（`app/parsers/`）

- **注册表单一来源**：`PARSERS = {"wechat": (WechatParser, ".xlsx"), "alipay": (AlipayParser, ".csv"), "jd": (JdParser, ".csv"), "unionpay": (UnionPayParser, ".csv")}`，经 `ParserSpec` / `get_parser_spec()` / `build_parser()` 取用；新增平台只需实现 `BaseParser` 并登记。
- `BaseParser.parse(file_path) -> list[dict]`，标准字段 tx_time/account/tx_type/merchant/amount/category/tx_id/remark。
- 平台识别（`detect.py`）：csv 读头部 64KB 样本定位列头行，按各平台特征列加权打分；识别失败回退文件名关键字（校验后缀匹配）。
- 容错：`csv_common.TolerantCsvParser` 列头别名宽容匹配（列名随平台版本漂移）；编码探测顺序 `utf-8-sig → utf-8 → gb18030`；微信 xlsx 用 openpyxl 只读模式。

### 10.3 AI 智能分类与报告（`services/ai_service.py`）

- 纯标准库 `urllib` 调 DeepSeek 兼容接口（temperature=0.1、JSON 输出、超时 60s）；**禁跟随重定向**（防 API Key 经 30x 外泄）；失败统一抛 `AIClientError(BizError)`。
- 归类三条路径：`classify_records`（单批 ≤50 条，输出按候选分类白名单校验）→ `classify_batches`（批间容错 + 时间预算）；导入增强 `enhance_import_records`；存量重分类 `reclassify_bills`（scope=unmatched/all、`after_id` 游标续跑、`_CLASSIFY_LOCK` 防重入、预算 240s / 上限 1000 条）。
- AI 报告：统计上下文 → prompt → 解析入库（`ai_reports` 表 upsert，`stats_summary` 存 JSON 供口径溯源），支持月/季/半年/年周期与归档管理。

### 10.4 NAS 目录导入与授权（`import_watch_service.py` / `nas_service.py` / `nas_authorization_service.py` / `trim_gateway.py`）

- 定时任务 `nas_watch`（30 分钟）：`scan_and_import()` 惰性 rglob 扫描配置目录（跳隐藏文件、后缀/大小过滤、`resolve` 防符号链接越界、上限 2000）→ 批量取既有 `content_hash` 指纹 → 逐文件判重、识别、导入；**单文件失败只记录不中断**，结果逐文件 upsert。
- 目录浏览所有路径经 `_resolve_in_root` 校验必须位于配置目录内（防 `..` 与软链越界）。
- 授权链路：经 Unix Socket `/var/run/trim_open_gateway_apiscope.socket`（`TRIM_API_TOKEN` 每次现读、单次 2s 超时）调 trim.file.* 查询用户可访问目录与 ACL；**网关不可用即降级**（返回 `available/reason/folders`），不抛 5xx。`uid_from_user_id` 用 crc32 低 31 位派生数字 uid。

### 10.5 定时调度器（`services/scheduler.py`）

- 函数注册表 `_REGISTRY`；每 tick（30s）扫描到期任务，经 `TaskDAO.try_claim` **原子认领软锁**后在线程池执行（锁机制见第 11 节）。
- asyncio 循环启动延迟 60s；**停机期间错过的执行合并补跑一次**；`SCHEDULER_ENABLED` 环境开关供测试关闭。

### 10.6 备份、恢复与导出（`backup_service.py` / `export_service.py`）

- 备份：categories/bills/budgets/assets 四节 JSON，`format_version=1`，含 `schema_version`、不含 id（跨库可恢复）。
- 恢复：合并模式按唯一键去重；覆盖模式先清空；`_clean_row` 白名单字段清洗防 JSON 注入；与迁移、导入两两互斥（共用 `RESTORE_LOCK`）。
- 导出：openpyxl 生成 xlsx；CSV 经 `_csv_safe` 防公式注入；下载响应头统一 `content_disposition`。

### 10.7 数据库在线迁移（`services/settings_service.py`）

`test_connection → migrate_database`：校验目标 ≠ 当前 → `ensure_driver` 装驱动 → 测试连接 → 目标建表 → `copy_database` 搬移 → `write_db_config_file` **原子写入**（临时文件 + `os.replace`，配合进程内锁，防并发读到半截 JSON）→ `activate_engine` 运行期切换 → 写 db 类型标记。另有历史流水认领（`claim_history`）与运行日志查看/下载（尾部 1MB）。

### 10.8 应用更新检查（`services/update_service.py`）

只做「**检查 + 引导下载**」：fpk 由平台解压到 `${TRIM_APPDEST}`，应用无权也不应替换自身安装目录，实际升级仍由用户在飞牛应用中心完成。

- **数据源**：`GET https://gitee.com/api/v5/repos/<owner>/<repo>/releases`（列表，匿名可用）。**刻意不用 `releases/latest`** —— 实测该接口不排除预发布，仓库最新一条是 dev 包时它会照样返回，正式版用户会被引导去下测试包；改为取列表后由本端过滤。接口与页面地址均由 `config.APP_REPO_URL` 推导，owner/repo 不在代码里重复书写。
- **渠道由本机版本号推导**（`channel_of`）：含预发布段（`-dev.N.gSHA`，见 `scripts/sync_version.py`）即测试渠道。正式渠道只比正式 Release（绝不把测试包推给正式用户）；测试渠道与**全部** Release 比对（正式版发布后测试用户也应收到提示）。不引入渠道配置项，也就不会被配错。
- **版本比较是零依赖的 semver 实现**（`compare_versions`），三个易错点都有测试锁死：① 预发布版本小于同号正式版（`0.7.1-dev.2` < `0.7.1`）；② 预发布段内的数字标识符按**数值**比较（`dev.10` > `dev.2`）；③ 版本号正则**要求三段齐全**，使仓库里的历史构建号 tag（`v`、`v23`、`v33`…）被剔除，而不是被解析成 `23.0.0` 而永远「最新」。
- **降级策略（离线部署是产品前提）**：网络不可达 / 限流 / 响应异常一律转 `ok=false` + 用户可读 `message`，HTTP 仍 200、不抛异常 —— 设置页不会因为「查不到更新」而弹错误浮层。**失败结果同样进缓存**，否则离线时每次进设置页都要白等一个超时。
- **结果缓存**：进程内 5 分钟 TTL；自动检查复用缓存，用户手动「重新检查」传 `refresh=true` 绕过。
- **下载直链优先级**：带版本号副本 `fn-finstat-v{版本}.fpk` → 裸名 → 任意 `.fpk`。刻意不识别渠道别名（`-latest` / `-dev`）：别名与同 Release 内其它 fpk 内容一致，为它在这里再维护一份渠道词表，只会多一处需要与 `sync_version.py` 对齐的地方。
- **更新说明按基版本匹配**：Release 描述取自仓库 `CHANGELOG.md`（整篇历史），需截出本次那一节。**不能无脑取第一节** —— CHANGELOG 在发版时才更新，而 dev 渠道每次 push 都发 Release，此时第一节是「上一个已发布版本」的日志，原样展示等于把旧版日志冒充本次说明。实现按**基版本**（`0.7.3-dev.5.g4cc0a6f` → `0.7.3`）匹配小节标题（测试包与其基线正式版共用同一节，设计如此），匹配不上就返回空串、界面隐藏该区块 —— 宁可少显示，不可错标。
- **权限**：普通账号即可（`CurrentUser`）—— 只读远端公开信息、不读任何本机数据，因此**不进** `_ADMIN_RULES`（已在 `tests/test_permissions.py` 的策略矩阵中固定）。
- 接口为 `GET /api/update/check?refresh=`，契约与取舍细节见 `docs/devlog/2026-09-17-应用检查更新功能实现.md`。

## 11. 并发控制与锁

| 锁 | 粒度 | 保护对象 |
| --- | --- | --- |
| `RESTORE_LOCK`（进程级） | 恢复/迁移/导入互斥 | 历史上迁移与备份恢复各用一把锁曾互相踩踏，现**复用同一把**；新增全局性操作优先复用已有锁 |
| `_CLASSIFY_LOCK` | AI 重分类防重入 | reclassify_bills |
| `TaskLock`（DB 软锁） | 定时任务跨触发认领 | `try_claim` 原子抢占；失败按 1/2/4 倍间隔退避；`LOCK_TIMEOUT=30min` 回收死锁；连续失败 5 次自动停用 |
| `_CONFIG_WRITE_LOCK` | 配置文件写入 | 配合原子写 |
| `_cache_lock`（`update_service` 模块级） | 更新检查结果缓存 | 只保护本模块的 `(时间戳, 结果)` 元组，**不涉及全局数据视图**，故刻意**不**复用 `RESTORE_LOCK` —— 否则一次更新检查会与备份/迁移互斥，纯属自伤 |
| `_EngineState` 内部锁 | 引擎替换 | 运行期切库 |

进程内共享可变状态用 `threading.Lock`；请求级上下文（请求 ID、请求会话）用 ContextVar，**必须成对 set/reset**（`finally` 中 `unbind_request_session(token)`，防跨请求串会话）。

## 12. 安全设计

| 要求 | 实现 |
| --- | --- |
| 信任边界 | `X-Trim-*` 头无条件信任 → 网关模式只绑 Unix Socket 且无头请求 401 拒绝；独立部署默认 127.0.0.1 + 来源校验中间件（Host 白名单防 rebinding、写方法 Origin 同源防 CSRF），非回环 HOST 启动告警（见第 1、6 节） |
| 路径脱敏 | 不把服务器绝对路径回传前端；解析异常回显前先脱敏 |
| 防 SSRF | 全部出站请求（AI 调用、通知 Webhook、更新检查）**禁跟随重定向**；更新检查的目标地址是代码内固定常量，不接受任何用户输入拼接 |
| 排序白名单 | `ORDER BY` 字段白名单映射，禁止拼接用户输入 |
| 字段白名单 | 更新接口只允许改白名单内字段（服务层 `_UPDATE_FIELDS`） |
| 上传限制 | 统一 `config.MAX_UPLOAD_SIZE`（10MB），文案三处共用 |
| 日志卫生 | `logger.exception` 记完整堆栈；对外 `msg` 只给通用文案；敏感信息不入日志 |
| 临时目录 | 打包/下载暂存目录用后即清 |
| NAS 越界 | 目录浏览限定配置目录内（`_resolve_in_root`）；扫描 resolve 防软链逃逸 |

## 13. 配置体系（`app/config.py`）

- **环境识别**：`IS_FNOS = bool(TRIM_PKGVAR)`；fnOS 下数据目录 `$TRIM_PKGVAR/finance`、临时目录 `$TRIM_PKGTMP/fn-finstat`；本地 `.local_data/`、`.local_tmp/`；支持 `.env.dev`（不覆盖已有变量）。
- **数据库配置四级优先级**：向导环境变量 > `db_config.json` > 通用环境变量 > 默认本地 SQLite。
- 信任边界开关：`FNOS_ALLOW_HEADERLESS=1`（排障逃生，fnOS 模式放行无头请求，默认关闭）；`HOST` 与派生的 `ALLOWED_HOSTS` / `HOST_IS_WILDCARD` 驱动来源校验中间件。
- 另管理 `ai_config.json`（DeepSeek api_key/base_url/model/enabled）与 `nas_config.json`（导入目录/归属用户）。
- 版本号唯一来源是根目录 `VERSION` 文件（`scripts/sync_version.py` 打包时同步，详见 `docs/开发规范/编译与构建规范.md`）。

## 14. 部署与设备端生命周期（`cmd/`）

**设备端布局**：`${TRIM_APPDEST}` 为应用目录（只读），`${TRIM_PKGVAR}` 为持久化目录（数据库、`venv/`、`app.log`、pid、锁文件），`${TRIM_PKGTMP}` 为临时目录。

| 脚本 | 职责 |
| --- | --- |
| `cmd/main`（start/stop/status） | 引入 `python312` 运行时 PATH（manifest 声明 `install_dep_apps=python312`）；venv 建在持久目录；注入 `LOG_FILE`；`nohup uvicorn app.main:app --uds $TRIM_APPDEST/app.sock` 启动；就绪探活等 socket 文件出现（15s 超时）；PID + `/proc/cmdline` 校验防 PID 复用误判；noclobber 锁文件做生命周期操作互斥；stop 为 TERM→10s→KILL |
| `install_callback` | 建数据/临时目录、建 venv、装依赖、按向导 db_type 装数据库驱动 |
| `config_callback` | 向导参数变更后同步驱动并重启生效 |
| `upgrade_callback` | 重装依赖（幂等补建 venv）；数据在 `TRIM_PKGVAR` 无需迁移 |
| `uninstall_init` / `uninstall_callback` | 先优雅停进程再动数据；按卸载向导 `wizard_purge_data` 决定数据去留（非法值一律保留） |

## 15. 测试体系（`tests/`）

- **50 个测试文件、627 用例**，覆盖解析器、DAO、服务、权限/中间件、迁移、调度器、NAS、通知、NL 查询、更新检查等；`pytest.ini` 将 `app.*` 的 DeprecationWarning 升级为 error。
- **夹具机制**（`tests/conftest.py`）：
  - `db`：独立临时 SQLite 库，经 `_STATE.activate()` **整体替换全局引擎**——DAO 统一走 `get_db()`，因此无需 mock 任何 DAO；
  - `client`：全新 FastAPI 只挂业务路由 + 与生产同一套异常处理器（保证错误契约一致），不触发 lifespan/init_db；
  - `ai_config_isolated`（autouse）：AI/NAS 配置与日志指向临时文件、清除密钥环境变量（防真实外呼）、关闭调度循环。
- 辅助工厂：`make_bill_records`（跨账号造数据必须用不同 prefix，`tx_id` 全局唯一）、`assert_report`。
- **外部网络一律不出现在单测里**：AI/通知经替换客户端函数或 `urlopen` mock；更新检查替换 `update_service._fetch_releases`（不依赖外网的「真实网络核对」另放 `.local_tmp/`，不进程门禁）。
- 编写要求（新增接口必须补测试：正常路径 + 权限 + 参数校验失败）与命令入口见 `docs/开发规范/后端开发规范.md` 第 9 节。
