## 1. 数据模型（schema v11）

- 新表 `reimbursements`：user_id（归属账号）/ title / status（状态机）/ note /
  received_amount + received_date（到账登记）/ created_at。
- `bills.reimb_id` 可空列 + 索引：NULL = 未挂报销单。
- **兼容迁移（`_v11_add_reimbursements`）**：把存量 `reimbursed=1` 的流水按账号
  归入「历史报销」（状态已结清，到账金额 = 合计），报销标记保留——既有报销
  筛选与导出口径零破坏。回填限定 `reimb_id IS NULL`，重复执行幂等。
- `bills.reimbursed` 布尔**保留并改为派生同步**：挂单置 1、摘除/移出/进回收站
  置 0——既有 `reimbursed` 筛选、批量标记、导出列全部零改动继续可用。

## 2. 状态机与规则

`待提交(pending) → 已提交(submitted) → 部分到账(partial) → 已结清(settled)`：

- 部分到账 / 已结清必须登记到账金额（>= 0）；回到待提交 / 已提交时到账登记
  由服务端清空；
- 不改状态、只登记到账信息时按当前状态做一致性校验；
- 只允许**支出流水**挂单；回收站流水、已挂其他报销单的流水拒绝并逐条提示；
- 流水进入回收站自动摘除关联（`BillService.delete` / 批量移入回收站钩子
  `BillDAO.clear_claims`）；删除报销单先摘除其下全部流水（标记复位）；
- **统计口径不变**：报销支出仍计入支出，报销单只跟踪回收进度，不改看板数字。

## 3. 接口（/api/reimb，数据按账号隔离）

`GET ""` 列表（含笔数与金额合计，OUTER JOIN 聚合）；`POST ""` 新建（待提交）；
`PUT /{id}` 状态流转 / 到账登记；`DELETE /{id}` 删除并摘单；
`GET /{id}/bills` 明细；`POST|DELETE /{id}/bills` 挂单 / 摘单。
错误码新增 **460xx 报销域**（REIM_INVALID=46001 / REIM_NOT_FOUND=46002）。

## 4. 备份（format_version 3 → 4）

- 新增 reimbursements 节（保留 id）；bills 行携带 reimb_id；
- 恢复：报销单无自然唯一键，插入后按业务三元组 `(user_id, title, created_at)`
  反查新 id，`bills.reimb_id` 重映射；映射不到的按孤儿计数（reimb_id 置空、
  报销标记保留）。
- 重复合并恢复同一备份时，报销单会重复（无自然键可去重）——已记录为已知
  边界；流水本身由 tx_id 唯一约束去重不受影响。

## 5. 前端

- 流水页工具栏新增「报销单」开关，展开报销卡片：列表（笔数 / 金额 / 状态
  徽章）、新建表单、状态下拉 + 到账金额 / 日期登记（按状态显隐）、「加入
  勾选 (N)」把流水页勾选的支出流水挂入该单、展开查看明细并逐条移出、删除。
- 挂 / 摘 / 删除后联动刷新流水列表并清空勾选（报销标记变化立即反映到筛选）。
- AppIcon 新增 wallet 图标。
