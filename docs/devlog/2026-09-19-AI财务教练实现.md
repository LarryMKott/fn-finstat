## 1. 隐私红线（计划核心要求的落地）

计划原文：「长期记忆只存本地结构化摘要，不外传原始流水」。

实现方式：
- **上下文只含结构化聚合摘要**：月均收支 / 储蓄率 / 分类支出 TOP5 / 当月
  预算进度 / 储蓄目标进度——全部由本地 DAO 实时计算生成；
- **原始流水永不外传**：不将任何单笔交易记录（tx_time / tx_id / merchant /
  amount）放进 DeepSeek 请求体；
- **长期记忆即本地数据库本身**：每次对话实时从 bills / budgets /
  asset_snapshots 重算上下文，无需持久化对话历史或摘要缓存；
- **对话历史由前端传入**（≤3 轮），服务端不存储。

测试 `test_context_contains_aggregates_not_raw_bills` 显式断言上下文不包含
单笔流水的 tx_time / tx_id / 日期等原始字段。

## 2. 实现

- `coach_service._build_context(user_id, today)`：收集近 6 个完整月的
  月均收支 / 储蓄率 / 分类 TOP5 / 当月预算 / 储蓄目标，拼为多行文本摘要；
- `coach_service.coach_chat(user_id, question, history, today, settings)`：
  system prompt（教练角色 + 5 条规则）→ 追问上下文（≤3 轮）→ 当前问题 +
  摘要 → `ai_service.chat`（复用既有 DeepSeek 通道与 SSRF 防线）→ 回答；
- 追问上下文只传问答文本，不重复摘要（摘要每次实时重算已含最新数据）；
- 校验：空 / 超长问题 400；未配置 API Key 抛 AIClientError。

## 3. 接口与前端

- `POST /api/coach/chat`：请求 {question, history?}，响应
  {question, context, answer}——context 随响应回传供前端展开口径；
- 看板新增「AI 财务教练」卡片：聊天气泡（用户右 / 教练左）、「口径」按钮
  展开发给模型的结构化摘要、输入框 500 字限制、追问自动携带 ≤3 轮上下文。
