## 交付内容（S：调度编排，计算与链路全部复用）

新增 `app/services/auto_report_service.py` + 调度任务 `report_monthly`（间隔
24h），在 `main.lifespan` 与既有任务一同注册。报告生成、归档、通知三段全部
复用已交付链路，本模块只做编排：

| 环节 | 复用 |
| --- | --- |
| 报告生成 | `ai_service.generate_report(user_id, "month", 上月)`（数字后端算好、模型只解释，费用 1 次/账号/月） |
| 归档 | `ai_service.archive_report`（按 (user_id, "month", 周期) 唯一键 upsert） |
| 就绪通知 | `generate_report` 内部的 `notify_service.notify_report_ready`（`report_ready` 事件已在通知中心注册，逐类可关） |

### 落定口径的落地方式

- **默认开、设置页可关**：`AISettings.auto_report_enabled`（默认 `True`，
  存量 ai_config.json 无此键时同样按开处理）；设置页 AI 卡片新增开关，
  经 `PUT /api/ai/config`（`auto_report_enabled` 字段）保存，审计文案同步记录。
- **「每月 1 日」在固定间隔调度底座上的实现**：任务**每日一查**，目标月恒为
  上一个自然月，**上月报告缺归档才生成**——首次满足条件多发生在 1 日；
  已归档（含用户手动生成过）即跳过，天然幂等、不重复计费；停机错过补跑由
  调度底座合并为一次，恢复后首个 tick 补上。查档走 `AIReportDAO.get_by_scope`。
- **生成失败只写日志 + 发 `task_failed` 通知**（决策原文）：按 账号+目标月
  作为去重键，每日重试至多提醒一次；**任务整体不抛错**——AI 服务临时故障
  不应触发调度失败退避（1/2/4 倍间隔）把任务连续失败自动停用，次日重试、
  次月自然恢复。
- **费用可见性**（决策建议项）：成功生成即累加 `DATA_DIR/auto_report_state.json`
  计数（按月滚动清零），`GET /api/ai/config` 以 `auto_report_generated` 下发，
  AI 卡片开关说明实时展示「本月已自动生成 N 份」。不用 task_runs 统计的原因：
  运行历史保留窗口仅 30 天，跨月计数会漏。

### 边界与取舍

- 逐账号独立生成（`BillDAO.distinct_user_ids()`，自 anomaly_service 的同名
  私有查询提升为 DAO 公共方法，两任务共用同一遍历口径）；单账号失败不影响
  其他账号。
- 目标月**无任何收支的账号跳过**：空月报告没有信息量，纯耗 API 费用
  （`StatDAO.summary` 收支双零判定）。
- 手动「立即执行」（自动化页）与调度走同一函数，幂等闸门保证不重复计费。

## 接口与前端

- `GET /api/ai/config`：`AIConfigOut` 新增 `auto_report_enabled`（默认 True）与
  `auto_report_generated`（非敏感，全部登录用户可见）；`PUT /api/ai/config`：
  `AIConfigUpdate` 新增 `auto_report_enabled` 可选字段，保存即生效。
- 前端 `AICard.vue`：新增「每月自动生成上月报告」开关（开启态说明带出本月
  已生成份数），随表单一并保存；配置说明补一句费用提示。

## 测试

`tests/services/test_auto_report.py`（8 例）钉住 §7.3 决策不被悄悄改掉：

- 默认开（裸配置 `auto_report_enabled is True`）；
- 关闭 / 未配置密钥：静默跳过、零 AI 调用；
- 正常链路：逐账号生成+归档+计数，同月重复执行命中归档闸门不再计费；
- 用户已手动归档上月报告：不重复生成；
- 目标月无收支：跳过且不调用；
- 生成失败：任务不抛错、`task_failed` 同月同账号至多一条、不留半成品归档；
- 计数跨月归零。

`tests/services/test_anomaly.py` 回归通过（`distinct_user_ids` 重构无行为变化）。
