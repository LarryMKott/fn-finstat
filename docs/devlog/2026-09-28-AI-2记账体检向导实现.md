## 交付内容（S：只读统计 + 一键跳转，零 AI 成本）

`data_check_service.data_check()` + `GET /api/stat/data-check`，仪表盘新增
「数据体检」卡片（HealthCard 之下，**有问题才渲染**，数据干净不占版面）。
未分类与脏数据是 AI 归类准确率的最大噪声源——体检不调 AI，却直接改善
AI 归类、报表、固定项与订阅识别的输入质量。

| 体检项 | 判定 | 一键跳转 |
| --- | --- | --- |
| 未分类流水 | `category = DEFAULT_CATEGORY("其他")` | ✅ `jump: {categories: ["其他"]}` |
| 商户名为空 | `merchant` NULL 或空串 | ❌ 流水筛选表达不了「空商户」，如实只给计数 |
| 金额为 0 的记录 | `amount = 0` | ❌ 同上 |
| 未记账月份 | 自 `max(首个记账月, 近 6 个月窗口起点)` 到当前月逐月查缺 | ❌ 信息项（当前月未记账也算提醒；新用户不倒查开户前月份） |
| 疑似重复导入 | 同日 + 同收支类型 + 同商户 + 同金额 ≥2 条，`(组数, TOP3 组)` | ✅ 逐组 `jump: {start=end=当日, merchants=[商户]}` |
| 无归属账号的流水 | `user_id = ""`（复用 `count_unassigned`） | ❌ 处理入口在 设置 → 数据库 迁移认领 |

口径细节：

- **疑似重复**的分组键含收支类型——「买 100 / 退款 100」是收支各一笔、
  类型不同不成组；**转账不参与扫描**（同日同额转账对是常态）；商户为空与
  金额为 0 的行由其他项呈现，不混入；
- **无归属账号**仅在网关多账号模式（当前账号 user_id 非空）下呈现且
  count > 0 才出现；本地模式当前账号即空串，该项无意义；
- 所有计数不含回收站（`deleted`）；
- 跳转复用 T-6.2 `billsFilterHandoff` 交接机制（与 AI 报告追溯、问账
  「存为筛选」同构）：读后清空、流水页自动套用筛选并展开高级筛选。

## 接口与前端

- 响应结构：`{checked_month, items[], problem_count, problem_total}`；
  items 每项 `{key, label, count, hint, jump, detail?}`——count 为 0 的项
  同样返回（jump 为 null），jump 仅在 count > 0 且筛选可表达时给出；
  疑似重复组的跳转口径挂在 `detail[].jump`。
- 前端 `DataCheckCard.vue`：仪表盘静默加载（`silent`，与其他卡片同模式），
  逐项 label + 计数 + 提示 + 「去处理」；重复组逐组列出（商户/条数/日期/
  金额 + 独立跳转）。

## 测试

`tests/services/test_data_check.py`（6 例）：干净账号全绿且 jump 全空；
未分类计数与跳转口径；空商户/零金额计数且不硬跳；未记账月份查缺含
「新用户不倒查开户前」与「当前月未记账」两个边界；重复分组（退款对与
转账不成组、跳转口径正确）；无归属项的网关/本地模式差异。
