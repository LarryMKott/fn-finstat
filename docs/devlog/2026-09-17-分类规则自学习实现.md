## Context

v0.6 第 3 批按「底座先行」推进：T-6.1 查询意图翻译层已交付，本批第二项为
T-6.3 分类规则自学习——让分类准确率随用户纠正**自动上升**，压低 AI 调用
（归类优先级明确为 **已学习规则 > 内置关键词 > LLM**）。

## 交付内容

### 数据模型（schema v6 → v7）

- `learned_rules`：`pattern`（商户关键词）+ `category`（目标分类）+ `hits`
  （纠正证据计数）+ `enabled`（手动停用开关）+ 时间戳；
  `(pattern, category)` 唯一约束做证据去重
- 迁移沿用 v4/v5/v6 策略：纯新表由 `create_all` 幂等创建，迁移函数只推进
  版本戳；`tests/test_migration_v7.py` 复刻「v6 老库 → v7」升级路径
- 规则**全局共享**（无 user_id 维度）：分类本身全局共用，与内置关键词/AI
  通道同口径；v0.7 引入账本维度后再评估是否按账本隔离

### 证据生成（纠正钩子）

- **单条编辑**：`BillService.update` 检测到分类实际变化时，以更新后商户名
  提取 pattern 记一次证据（改成相同分类不算纠正；纠正到「其他」不产生证据）
- **批量设置分类**：一次批量动作对**去重后的商户 pattern** 各记 1 次证据，
  不按流水条数膨胀 hits；已在目标分类的流水跳过
- pattern 提取：剔括号片段（「瑞幸咖啡（朝阳门店）」→「瑞幸咖啡」）→
  剥首尾装饰 → 长度 2..64（列宽裁剪）
- 纠正钩子 best-effort：学习失败只记日志，绝不影响记账主流程

### 规则生效与匹配

- **阈值**：同方向纠正累计 `hits >= 2`（`CONFIRM_THRESHOLD`）才参与匹配
  （REQ-AIC-001：改 2 次、第 3 笔起生效），避免一次误改污染全库
- **冲突**：同 pattern 指向不同分类时取 hits 最高者；平票取先建者；
  再次纠正某方向会累加证据并**自动恢复启用**（推翻手动停用）
- **多 pattern 命中**：pattern 更长者优先（更具体的商户名优先于宽泛词），
  大小写不敏感（与内置关键词匹配同口径）
- 兜底：规则指向的分类已不存在时不生效；规则读取失败按无规则处理

### 导入归类优先级（`import_service._parse_and_normalize`）

顺序调整为：**已学习规则 →（未命中）解析器自带分类 / 内置关键词 →（仍为
「其他」）AI 二次归类**。命中规则的流水覆盖解析器自带分类（用户纠正过的
商户以纠正为准），且不再进入关键词匹配与 LLM 路径；整批命中时运行日志
记 `已学习规则归类 N 条`。

### 管理接口（设置页规则列表，写操作仅管理员）

- `GET /api/settings/learned-rules`：全部规则按 hits 降序，附
  `active`（enabled 且证据达标）计算字段
- `PUT /api/settings/learned-rules/{id}`：改目标分类 / 启停
- `DELETE /api/settings/learned-rules/{id}`：删除（证据清零，可重新积累）
- `_ADMIN_RULES` 增加 PUT/DELETE 拦截（`tests/test_permissions.py` 矩阵补 3 例）；
  前端设置页规则列表 UI 留待 T-6.2 一并交付（接口先行）

  与 `black --check` 通过

## 边界与后续

- 规则编辑页/规则列表 UI 未做（T-6.2 对话界面同一批交付设置页区块）
- 学习证据不随流水删除回滚（删账单不撤销已记证据）；批量纠正按动作去重
  而非条数，语义为「一次用户动作 = 一次纠正」
- 存量重分类（`POST /api/ai/classify`）不消费学习规则——它是显式的 AI
  重跑动作，与导入自动归类优先级是两条路径；是否让学习规则参与存量重写
  留待使用反馈
- 版本号四处同步留待 v0.6 整体收口发布时执行
