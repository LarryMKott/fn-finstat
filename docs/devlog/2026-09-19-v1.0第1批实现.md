## 1. 财务健康评分（T-1.3）

`GET /api/stat/health`，只读计算不落库。三分项加权（0.4 / 0.3 / 0.3）：

- **储蓄率**（40%）=（月均收入 − 月均支出）÷ 月均收入，取近 6 个完整自然月
  （未记账月计 0，不剔除）；≥20% 满分、≤0% 零分，线性内插
- **负债率**（30%）= 最新资产快照负债合计 ÷（资产 + 负债）；≤30% 满分、
  ≥70% 零分
- **应急金月数**（30%）= 最新快照资产合计 ÷ 月均支出；≥6 个月满分
- 缺数据的分项**不计分**，总分按剩余权重归一，并在 `items[].hint` 说明原因
  （不造假数字）；等级：≥80 优秀 / ≥60 良好 / ≥40 一般 / <40 待改善
- **口径完全公开**：`items[].formula` 由后端随响应下发（含窗口区间与当前
  月均值），前端原样展示；无快照时负债 / 应急金如实提示「无法评估」

## 2. 储蓄目标（T-1.4）

`savings_goals` 新表（name / target_amount / start_date / target_date / note）。
**进度不是手工存值**：`进度 = 目标起始日以来（收入 − 支出）的累计净结余`，
由流水实时计算——记账行为本身推进目标，无需手动打卡。达标（saved ≥ target）
自动 `done`；填写目标日期时给出「距目标日 N 个月、月均需再攒 X 元」参考口径。
接口 `/api/savings-goals`（GET / POST / PUT / DELETE，按账号隔离，起始日不可改）；
前端资产页新增目标区块（进度条 + 达标徽章 + 删除）。
