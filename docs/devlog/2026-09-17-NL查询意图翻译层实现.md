## 交付内容

### 结构化查询对象（口径）

所有问法最终收敛为一个白名单查询对象（`app/schemas/nl_query.py::NLQuerySpec`）：

```
time: {start, end, label}        # YYYY-MM-DD，两端含当日
categories: str[≤3]              # 必须来自真实分类表（CategoryDAO）
merchants: str[≤3]               # 子串匹配（LIKE，%/_ 转义）
metric: expense | income | count
group_by: none | category | merchant | month | day
order_by: amount_desc | amount_asc | count_desc | count_asc | key_asc
limit: 1..100
```

### 两段式翻译（`app/services/nl_query.py`）

1. **规则优先（零成本路径）**：时间表达正则表（相对周期/绝对日期/区间/ISO，约 20 类）、
   指标关键词、分组提示、TOP-N；分类按真实分类名长度优先子串匹配（「其他」作为兜底
   分类也是高频口语词，规则路径刻意不匹配，LLM 路径仍可选）；商户关键词走四类启发式
   （引号 / 在·给+动词 / XX的花费 / XX花了），候选含时间·疑问·汇总等字样即拒绝；
   比较类问法（"A 和 B 哪个月多"）单条查询对象表达不了，规则路径主动让位 LLM。
2. **LLM 兜底**：复用 AI 通道（`ai_service.chat`，同一 SSRF 防线），JSON 强约束输出
   上述查询对象；`_normalize_llm_spec` 把模型输出收敛进白名单——非法枚举回退默认、
   分类不在真实分类表即丢弃、日期解析失败置空、limit 钳制 1..100、**非白名单字段
   （含 user_id / sql 之类注入企图）一律忽略并记 warning**。

### 执行与答案（数字全部来自数据库）

- `StatDAO.nl_aggregate`（新只读方法）：分组维度/排序全部映射白名单列表达式，
  user_id 强制注入，全绑定参数；总口径单独一次不分组汇总，分组行 limit+1 探测截断
- `BillDAO.nl_detail_rows`（新只读方法）：同筛选按金额降序取 ≤20 条明细样本（口径透明）
- `build_criteria` 扩展可选 `categories`（IN）/ `merchants`（转义 LIKE OR），全存量调用不受影响
- 答案文本由后端按结果确定性生成（含时间口径 + 筛选条件 + 覆盖笔数），模型不生成任何
  展示文本——无数据时明确说「没有查询到流水」，不允许编造

### 降级与费用上限

- 未配置 AI / 调用失败 / 输出非法 → 降级规则路径执行，`source=fallback` + `degraded`
  + `message` 明确告知原因（绝不静默）
- 单日 LLM 翻译调用上限 100 次（进程内计数，`LLM_DAILY_LIMIT`），超限规则路径接管并
  提示——v0.6 出口标准「AI 调用有上限」的第一处落地（规则路径不计数）
- LLM 调用超时 8s（交互路径验收口径 <8s；报告生成/批量归类仍为 60s）

### 接口（`app/api/nl_query.py`，已注册 main 双前缀）

- `POST /api/nl-query`，所有登录用户可用（数据按 user_id 天然隔离，无管理面）
- 请求体 `extra="forbid"`：除 `question` 外任何字段（含 user_id）直接 422；
  question ≤200 字
