## 1. 背景与范围

计划对 T-6.4 的要求：预算建议（近 6 个月同分类支出中位数 × 调整系数，剔除一次性大额，给区间与采纳按钮）+ 现金流预测（识别固定项，输出未来 30 / 90 天余额曲线，P50 与 P90 悲观线），验收要求口径可查看、可逐项排除重算、样例数据与人工核算误差 < 5%、建议可一键采纳后微调。

原则沿用 T-6.1 的信任红线：**所有数字由后端按确定规则计算，模型不参与**——本功能完全不需要 AI，是纯规则计算。

## 2. 技术方案

### 2.1 预算建议（`budget_suggestions`）

- 窗口 = 目标月（默认当月，可指定）之前最近 **6 个完整自然月**；
- 一次性大额剔除：单笔金额 > 该分类「月度支出中位数 × 3」即剔除并逐条列出。**与计划原文「> 3σ」的偏离及理由**：小样本下 σ 会被离群值本身抬高（300/300/300/20000 时 mean+3σ≈30000，永不触发），中位数基准的 3 倍同样拦住单次大额采购且对样本量不敏感；
- 出现月份 ≥ 3 的分类才给建议；建议 = 剔除后非零月合计的中位数，区间 = × 0.9 ~ × 1.1（调整系数）；
- **采纳不新增写接口**：建议接口只读，采纳 = 前端调既有 `PUT /api/budget`，之后走既有「编辑」手动微调。

### 2.2 现金流预测（`cash_flow`）

- 窗口 = 今日之前最近 **3 个完整自然月**；数据未覆盖整个窗口时如实提示「固定项识别可能偏保守」；
- 固定项 = 同商户（区分收支类型）在窗口内每个完整月都出现，且各月合计 max/min ≤ 1.25（金额同一区间）；扣款日取该商户流水出现最多的日号；月度金额取中位数；
- 可变支出 = 窗口内支出扣除固定项商户后的月度合计；**P50 取非零月中位数**（尚未记账的月份合计为 0，混进中位数会系统性低估）、P90 取观察期最差月份（不虚构分位数）；日均按 30 天/月折算，便于人工核算；
- **可变收入不外推**（偶发收入摊进未来会虚增余额），固定收入照常按扣款日投影；
- 起点余额：有资产快照 = 最近快照净资产 ± 快照日之后的收支净额（避免快照后消费被双计）；无快照 = 全部流水净额。来源随响应回传（`start_source`）；
- 逐项排除：`exclude` 参数收固定项 key（`tx_type:商户`），**被排除项的流水回落进可变支出**（不凭空消失），未知 key 忽略并记日志。

### 2.3 数据访问与安全

- `StatDAO.forecast_rows` 新只读方法：取 tx_time / tx_type / merchant / category / amount 窄列（「同商户每月出现且金额同区间」无法用 SQL 表达，聚合在应用层）；`user_id` 强制注入，条件全部绑定参数；
- 复用 `AssetDAO.trend`（最近快照净资产）与 `StatDAO.summary`（快照后净额），无新写路径；
- 权限面：两个新端点均为只读 GET，不进 `ADMIN_RULES`，账号隔离由 DAO 的 user_id 过滤保证（与其他统计接口同策略）。

## 4. 测试与验证

`tests/test_forecast.py`（13 例）覆盖：

- 固定项识别：稳定房租/工资识别成功（金额与扣款日）、金额波动超带宽不识别、缺席月份不识别、单月出现的商户不识别、历史不足时固定项为空并提示；
- **人工核算 < 5%（验收项）**：房租 3000×3 + 工资 10000×3 + 可变 900/1000/1100 的样例，P50 终点 = 36000、P90 终点 = 35700，与接口输出误差 < 0.003%（逐日 round2 漂移 ≤ 1 元），另断言 P90 恒 ≤ P50；
- 排除重算：排除房租后固定项消失、其流水回落进可变（月度合计 3900/4000/4100、P50=4000）；未知排除 key 忽略；
- 预算建议：一次性大额（20000）按中位数×3 剔除且建议仍为 1000、区间 900~1100；不足 3 个月（含剔除后不足）不给建议；非法月份 400；
- 采纳链路（API 级）：建议 → `PUT /api/budget` → 总览可见、建议接口回显 `current_budget`；
- 起点余额：有快照时 = 快照净资产 + 快照日后净额（50000 + 10000 − 2100 = 57900 实测一致）、无数据时曲线为直线；
- 参数校验：horizon 5/200 → 422；账号隔离：B 账号看不到 A 的固定项与余额。

全量：后端 `pytest` 648 例通过；前端 `npm run lint` / `build` / `test` 通过。

## 5. 已知边界与后续

- 固定项以「商户名完全一致」为粒度：同一订阅换商户名（如平台改名）会断档一个月后重新识别；
- 多笔固定项（如每周买菜）整月合计投影在出现最多的一天，曲线形状近似、量级正确（口径区有说明）；
- P90 取观察期最差月，样本只有 3 个月，分位线偏保守；窗口拉长（如 6 个月）可后续按反馈调整；
- 前端建议面板未展示被剔除大额的明细清单（只显示笔数），需要逐笔核对时可查后端日志/后续按需加折叠；
- T-6.2（对话式查账界面）为 v0.6 第 3 批下一任务。
