## 1. 做了什么

把「我的账本」升维到「我们家的账本」：多个飞牛账号组成一个家庭空间，成员各自
记账（数据仍按 `user_id` 隔离），家庭页只展示聚合值；账本切换与管理界面同批交付。

| 交付物 | 位置 |
| --- | --- |
| `families` / `family_members` 表 | `app/db/models.py::Family`、`FamilyMember` |
| schema v9 迁移（纯新表） | `app/db/migrations.py::_v9_add_family_tables` |
| 家庭 DAO / 服务 / 接口 | `app/db/dao/family_dao.py`、`app/services/family_service.py`、`app/api/family.py` |
| 家庭数据贯通备份恢复与跨库搬移 | `app/services/backup_service.py`、`app/db/copy.py` |
| 前端家庭共享页 | `frontend/src/components/FamilyPanel.vue`、`frontend/src/api/family.js` |
| 账本切换（看板/流水）与设置页账本管理 | `DashboardPanel.vue`、`BillsPanel.vue`、`settings/LedgerCard.vue` |

## 2. 关键设计决策

### 2.1 聚合 = 成员之和：按成员逐个查询后在 Python 合并

验收底线是「家庭页汇总数与各成员实际之和一致」。做法是不动 `StatDAO` 的单账号
签名，对每个成员各做一次 summary / category_pie / count（家庭规模小，N 次小索引
查询），在服务层累加——加总口径天然逐项可核对，也顺带得到逐成员收支条数
（`members` 数组），前端可直接展示「谁花了多少」。

### 2.2 隐私边界：聚合永远可见，明细显式 opt-in（REQ-FAM-002）

- 既有接口本就按 `X-Trim-Userid` 隔离，成员天然看不到他人明细——家庭维度不新增
  任何「看别人数据」的通道，唯一入口是 `GET /api/family/members/{user_id}/bills`；
- 该入口由 `families.allow_detail_view` 门控，**默认关闭**，关闭时一律 403
  （含家庭管理员——隐私边界由家庭设置决定，不因角色放行）；
- 开关仅家庭管理员可改；家庭页汇总对全部成员可见（REQ-FAM-003，不限于管理员）。

### 2.3 家庭管理员 ≠ 飞牛应用管理员

家庭管理员是**家庭内部角色**（创建人），与 `X-Trim-Isadmin` 的应用管理员无关。
因此家庭路由全部挂 `CurrentUser`，角色校验在服务层收口
（`_require_family_admin`），**不进** `core/permissions` 的应用级管理面策略表——
与「全局影响操作才进管理面」的既有约定一致（家庭操作只影响本家庭）。

### 2.4 生命周期守卫

- 一个账号至多加入一个家庭（`family_members.user_id` 全局唯一，约束兜底并发）；
- 管理员在还有成员时不能退出（须解散或先移除成员）；最后一人退出自动解散，
  避免空家庭残留；
- 解散/移除只删关联行，成员各自的账单数据不受影响（删账本 ≠ 删数据的同款底线）；
- 邀请码 8 位、去易混淆字符字母表（0/O、1/I/L），`secrets` 生成；重新生成即
  覆盖旧码使其失效。

### 2.5 schema v9：纯新表迁移，模式同 v4~v7

`families` / `family_members` 由 `init_db` 的 `create_all` 幂等建表，迁移函数只推进
版本戳，无列级变更、无数据回填，三方言零差异（v8 的 SQLite 重建表是上一批的
特例，不是常态）。

### 2.6 备份与搬移：家庭按**邀请码**重映射（与账本按名重映射同款）

- 备份新增 `families` / `family_members` 节；families 保留 `id`（重映射依据），
  成员行不带 id；恢复时按邀请码把成员行的 `family_id` 映射到目标库新 id，
  码映射不到的家庭按坏行计 `skipped`（不落孤儿成员）；
- 合并模式下成员 `user_id` 已在本家庭时由唯一约束去重，保持本家庭归属；
- 跨库搬移（`copy_database`）同口径；PG 序列同步补上两张家庭表。

## 3. 接口一览

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/family` | 登录用户 | 我的家庭（未加入 `data: null`）；邀请码仅管理员视角返回 |
| POST | `/api/family` | 登录用户 | 创建家庭，创建人成为管理员；已在家庭 400 |
| POST | `/api/family/join` | 登录用户 | 凭码加入；码无效 404、已在家庭 400 |
| POST | `/api/family/leave` | 登录用户 | 退出；管理员有成员时拒绝（400） |
| DELETE | `/api/family` | 家庭管理员 | 解散家庭 |
| PUT | `/api/family/settings` | 家庭管理员 | 明细可见性开关 |
| POST | `/api/family/invite/regenerate` | 家庭管理员 | 重新生成邀请码 |
| DELETE | `/api/family/members/{user_id}` | 家庭管理员 | 移除成员 |
| GET | `/api/family/summary?month=` | 家庭成员 | 月度聚合（totals/members/categories） |
| GET | `/api/family/members/{user_id}/bills` | 家庭成员 | 成员流水（只读，`allow_detail_view` 门控） |

## 4. 前端

- **家庭共享页**（新导航项「家庭共享」）：未加入时创建/加入双入口；加入后展示
  成员列表（管理员可移除）、邀请码（复制/重新生成）、隐私开关、退出/解散；
  月度汇总卡（收入/支出/结余）+ 逐成员收支表 + 全员分类条形榜；
  `allow_detail_view` 开启后成员行出现「看流水」（只读，前 50 条）。
- **账本切换**：统计看板筛选栏与流水页筛选栏各加「账本」下拉（全部账本 = 不按
  账本过滤，与后端 None 语义一致）；流水页重置筛选同步清空。
- **设置页「账本管理」卡片**（`LedgerCard`）：列表（含流水条数）、新建、改名、
  删除（默认账本禁删；删除前确认并入默认账本的条数）。
