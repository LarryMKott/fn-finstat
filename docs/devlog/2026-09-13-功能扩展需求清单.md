## 1. 角色定义与术语

| 角色 | 说明 | 主要诉求 |
| --- | --- | --- |
| **单人用户** | 自己记账自己看的主力用户 | 少动手、看得懂、数据安全 |
| **家庭管理员** | 建家庭空间、邀请成员、管全局配置 | 能看到全家总账、能管权限 |
| **家庭普通成员** | 只记自己的账、看家庭汇总 | 隐私边界清楚、不被打扰 |
| **报销用户** | 有垫付 / 报销需求的上班族 | 清楚还有多少钱没回来 |
| **极客 / 集成用户** | 想用自己的脚本或 AI 助手对接数据 | 有开放接口、鉴权可靠 |
| **运维者** | 装应用、看日志、做备份的人（常与单人用户是同一人） | 出问题能查、能回退、不丢数据 |

| 术语 | 定义 |
| --- | --- |
| 账本 | 一册独立的收支集合（个人 / 家庭 / 旅行 / 装修等），带独立统计口径 |
| 家庭空间 | 多个飞牛账号的聚合容器，成员各自持有账本，家庭页展示聚合值 |
| 规则 | 由用户纠正行为自动学到的"商户关键词 → 分类"映射 |
| 口径 | 一次查询或统计所采用的时间范围与筛选条件集合，必须对用户可见 |
| 固定项 | 近 3 个月每月出现、金额落在同一区间的商户（订阅 / 房租 / 还款） |

## 2. 优先级与状态定义

### 2.1 优先级（用户价值 + 依赖关系双维度判定）

| 级别 | 判定标准 | 处理原则 |
| --- | --- | --- |
| **P0** | 缺了它该版本不成立；或者是其他需求的硬前置；或涉及数据安全/正确的底线 | 必须完成，未完成则版本不发布 |
| **P1** | 显著影响体验或信任，但不做也能用 | 目标范围内尽量完成；资源紧张时可顺延并记录 |
| **P2** | 锦上添花、受平台或外部条件限制 | 明确标为可延后，不阻塞版本 |

> 判定依据（沿用脑洞清单）：用户价值密度 × 复用现有资产程度 × 差异化 × 风险合规。
> **注意**：P0 不等于"现在做"——它表示"做这个版本时不能少"，排期顺序见开发计划第 5 章。

### 2.2 状态流转

`候选` → `已确认`（需求评审通过） → `已排期`（进入具体版本） → `实现中` → `已验收`（验收标准全部勾选） → `已发布`
任一环节可退回 `候选` 并附退回理由。**需求编号一经分配永不复用。**

## 7. 关键需求验收标准（P0 细化）

### REQ-AUT-003 错过补跑

- **Given** 一个周期为每日的抓取任务，应用已停止 3 天
- **When** 应用重新启动
- **Then** 启动后 60s 内补跑 **1 次**（不是 3 次）；补跑产生的数据与正常执行一致；重复内容不重复入库

### REQ-ING-001 邮箱账单自动抓取

- **Given** 已配置收信邮箱且存在 3 封未处理账单邮件
- **When** 触发一次抓取
- **Then** 返回「新增 N / 跳过 M / 失败 K」计数；N + M + K 与邮件内容一致
- **And** 再次触发同一批邮件时 N = 0、M = 3（全部识别为已处理）

### REQ-ING-003 NAS 目录自动导入

- **Given** 目录中存在 A（已导入过）、B（新文件）、以及被替换内容的同名 A
- **When** 调度周期触发扫描
- **Then** 仅导入 B 与"新 A"两条；旧 A 不被重复导入；失败文件记录原因并退避，不无限重试

### REQ-QRY-002 查询口径可追溯

- **Given** 用户提问"上个月奶茶花了多少"
- **When** 系统返回答案
- **Then** 回答必须同时给出：时间范围、命中的分类 / 商户条件、覆盖流水条数
- **And** 用户可展开看到参与计算的流水明细入口

### REQ-QRY-003 查询越权防护

- **Given** 账号 X 发起查询，而系统中存在账号 Y 的流水
- **When** 构造任何形式的查询（含让模型输出越权条件的输入）
- **Then** 返回结果中 Y 的数据条数为 0；越权尝试被记录到日志
- **And** 非白名单字段与非法枚举值一律被拒绝

### REQ-AIC-001 分类规则自学习

- **Given** 商户"×××咖啡"的流水最初被归入"其他"
- **When** 用户连续 2 次手动改分类为"餐饮"
- **Then** 第 3 次导入该商户流水时自动归入"餐饮"
- **And** 该路径**不产生 LLM 调用**（可通过日志确认）

### REQ-RPT-001 报告数字可追溯

- **Given** 已生成一份 AI 月度报告
- **When** 用户点击报告中的任一数字
- **Then** 可看到该数字的计算来源（区间 + 筛选条件 + 明细入口）
- **And** 报告中的数字与同月看板显示的数字完全一致

### REQ-FAM-002 家庭明细隔离

- **Given** 家庭中有成员 A、B，各自有流水
- **When** A 访问家庭页与任何查询接口
- **Then** A 看不到 B 的任何明细；家庭页只展示聚合值
- **And** 即使直接构造请求指定 B 的标识，也被拒绝

### REQ-DAT-001 破坏性迁移的数据安全

- **Given** 一个 v5 的既有库（含流水 / 预算 / 资产快照）
- **When** 升级到 v6 并启动
- **Then** 迁移前自动生成 `bill.db.bak-v5`；迁移后逐项核对条数与金额 0 丢失
- **And** 迁移失败时**拒绝启动**而不是静默跳过；可从备份回退

## 9. 未采纳需求及理由

| F8 报税估算 | 合规敏感、受众窄，误算带来的风险大于收益 | 不采纳 |

| I 组全部脑洞（碳足迹 / 音箱记账 / 超支限速等） | 趣味价值为主，不构成需求；如需保留传播点，优先考虑 B7 年度账单长图 | 延后（Backlog） |

| A4 银行 PDF 对账单 | 版式多变，需先验证 2–3 家模板的稳定性再决定是否立项 | 待预研 |
| A5 拍照 OCR 记账 | 依赖移动端与 OCR 质量，投入产出不确定 | 待预研 |

## 10. 需求变更与冻结约定

1. **编号永不复用**：需求范围变化一律新增编号，并在原编号上标注「被 REQ-XXX 取代」。
2. **范围冻结点**：某版本进入开发前冻结该版本 P0 集合；开发期间新增需求一律进下一版本，除安全 / 数据正确性缺陷外不做插入。
3. **验收不留活口**：需求状态仅在验收标准**全部勾选**后才可置为「已验收」，部分完成保持「实现中」。
4. **口径变更需回写**：若预研结论与需求假设冲突（例如飞牛推送通道确认不存在），先更新本文档再改代码。
5. **优先级可调但需留痕**：任何优先级调整需在原条目上记录调整日期与原因。
