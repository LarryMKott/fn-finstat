## 交付内容（M，零 AI 成本，零新增依赖）

「上次给家里人买东西花了多少」这类模糊问法与备注往往**无字面重叠**，关键词
检索在该场景基本失效（§7.4 实测 Top10 命中 1/9）。本次按拍板路线把验证脚本
`scripts/verify_note_search.py` 的原型生产化——**纯标准库 TF-IDF + 余弦相似度**，
不引入 sentence-transformers/torch（≈1.5GB 违背零依赖红线），也不做 LLM 打标
（留作真实数据上不够用时的第二阶段增强）。

- `app/utils/note_search.py`：`tokenize()`（中文单字 + 相邻双字 2-gram +
  英文数字词，零分词库的必然口径）+ `TfIdfIndex`（平滑 IDF，余弦打分，
  零分与低于阈值的噪声不返回，同分按索引下标稳定排序保证可复现）。
- `app/services/note_search_service.py`：`search_notes()` 编排——
  `BillDAO.note_search_rows()` 窄列（id/商户/备注，只取有文本的流水）→
  **现场建索引**（几千条毫秒级，不做持久化缓存）→ Top-K → `BillDAO.list_by_ids()`
  回填展示行（经 `BillOut` 过滤 user_id/deleted 等内部字段）并附加 score。
- 条数上限 `NOTE_SEARCH_MAX_DOCS=3000` 按 id 倒序取最近的（建索引 O(总词数)
  毫秒级，更旧流水对「找最近那笔」价值也最低）；超限置位 `caliber.capped`
  供前端提示。

**关键口径决策：相关度不做硬性阈值过滤**。校准时发现单字巧合可能给出
高分（「区块链投资」命中「社区」卫生站 0.28，反超真实命中「父亲节礼物」
0.10），硬阈值既切不掉这类噪声又会误伤短查询——故相关度仅作**相对排序分**
（0~1）随行返回，由前端展示百分比、口径文案注明「不代表绝对语义」。
停用词（的/了）刻意不过滤：「给家里人买东西」依赖单字「给」「买」命中
「给老妈买的按摩仪」，加停用词会破坏拍板数据的复现。

**实测对齐**：§7.4 评测语料（35 条内置语料 × 5 组查询）Top10 合计命中 **9**，
与脑洞清单拍板数据完全一致（生产化未损失原型效果）。

## 接口与前端

- `GET /api/bill/note-search`（挂在 `/{bill_id}` 路由之前防路径吞并）：
  `q` 必填（1~64 字）、`top_k`（1~50，默认 10）、`tx_type`/`ledger_id`
  可选（检索前过滤）。响应 `{query, indexed, results[], caliber}`，
  results 行结构与流水列表一致（BillOut 口径）+ `score`；服务层空检索词
  抛 `BizError(BILL_INVALID)` → 400。
- MCP 工具 8 → **9** 个：`query_note_search`（q 必填、top_k/tx_type 可选），
  纯文本 Top-N 摘要（含相关度两位小数），经既有 `@tool` 装饰器注册，
  JSON-RPC 协议层零改动。
- 前端流水页（BillsPanel）：筛选栏尾部新增「语义检索」入口（新增 `search`
  图标），展开独立面板——输入模糊描述 → 命中列表（日期/商户/备注/金额/
  相关度%），与下方流水列表的筛选、分页、批量操作互不干扰；空结果给
  「换一种说法」提示，语料达上限提示仅检索最近 3000 条。

## 测试

- `tests/services/test_note_search.py`（7 例）：无字面重叠命中（前提自检
  词组级零交集）+ 行结构/内部字段过滤；就医问法命中药房流水；纯英文无
  交集返回空且口径回传；top_k 钳制与语料上限 capped 置位；空/空白检索词
  抛 BizError；账号双向隔离；tx_type 检索前过滤。

  命中结构与 caliber；网关身份隔离（A/B 互不可见）；空白 q → 400 +
  BILL_INVALID。

  `test_tools_call_note_search`（模糊命中 + 空检索词 isError）。
