## 1. 背景与问题

改造前，加载反馈是**各组件各自维护**：`BillsPanel` 有 `batchBusy` / `aiBusy`，`NasImportBox` 有
`nasSaving` / `nasLoading` / `nasImportingAll` / `nasBusy` 四个标志，`AutomationCard` 每个任务一份
`uiState`，而 `DashboardPanel`、`BudgetSection`、`HeatmapSection`、`YearCompareSection`、`BillModal`、
`BackupCard`、`AppearanceAboutCard` 等**完全没有加载提示**。由此产生四类问题：

| 问题 | 具体表现 |
| --- | --- |
| 反馈缺失 | 切到看板后四张图并发请求，界面静止数秒，用户不知道在加载还是卡了 |
| 状态各说各话 | 同一动作在不同页面文案/交互不一致；有的锁按钮有的不锁 |
| 可重复触发 | 只有部分按钮做了 `:disabled`，连点会产生重复流水/重复快照 |
| 失败无提示 | 部分 `catch` 只 `toast`，部分什么都不做，请求失败后界面毫无变化 |

## 2. 方案

沿用项目既有的「模块级 `reactive` 状态 + 导出触发函数 + 全局挂载组件」单例模式
（与 `toast.js` / `AppToast.vue`、`composables/useConfirm.js` / `AppConfirm.vue` 同构），
新增一对文件：

| 文件 | 职责 |
| --- | --- |
| `frontend/src/composables/useLoading.js` | 任务状态中心：`runTask()` / `isBusy()` / `loadingState` / `dismissLoading()` |
| `frontend/src/components/AppLoading.vue` | 浮层组件，`Teleport to="body"`，在 `App.vue` 挂载一次 |

业务侧只声明「任务名 + 步骤文案 + 干活的函数」，显示、关闭、防重入、异常收尾全部由 `runTask` 负责。

### 2.1 四态反馈

`loadingState.phase` 取值 `running | success | error | idle`：

- **开始/进行中**：环形 CSS spinner + 任务名 + 步骤文案，可选确定进度条（不确定时走左右循环动画）
- **完成**：勾选图标 + 完成文案，停留约 0.9s 后收起
- **失败**：警告图标 + **错误原因原文**，停留 8s，并提供「关闭」按钮可手动关掉
- **隐藏**：栈空时 `visible=false`

`task(update)` 的 `update` 参数支持两种写法：`update("正在解析第 3 个文件…")` 或
`update({ detail, progress, title })`，供批量任务实时汇报进度。

### 2.2 防重入

每个任务用 `key` 标识，语义是「防重入粒度」：

| `mode` | 行为 | 适用 |
| --- | --- | --- |
| `queue`（默认） | 同 key 已在执行时**直接拒绝**，并 toast「正在执行，请稍候」 | 写操作：提交、删除、迁移、导入 |
| `latest` | 允许新请求接管，旧响应回来时**不允许覆盖新状态** | 查询：翻页、切时间范围、切年份 |

按钮侧统一用 `:disabled="isBusy('xxx')"`，组件内不再保留自己的 `busy` ref。

### 2.3 任务栈（关键设计）

浮层是**单例**，但同一时刻可能有多个不同 key 的任务在跑（切到看板时汇总/趋势/预算/热力图/年度对比
并发加载）。如果「谁先完成谁关浮层」，先返回的请求会把仍在进行的任务提示提前关掉。

因此内部维护一个活动任务栈 `active[]`：

- 展示**最近发起**的任务（用户刚点的操作优先反馈）；
- 任务结束后进入停留期，计时到才出栈，出栈后自动回落到更早的仍在跑的任务；
- **只有栈空时才真正隐藏**，从机制上保证不会「提前关掉」也不会「卡死」。

### 2.4 不阻塞、不跳动

- **不铺遮罩**：浮层 `position: fixed` + 容器 `pointer-events: none`，仅卡片本身可点，
  加载期间页面仍可滚动和切换；
- **不引起布局跳动**：不插入占位元素，只有 `opacity` / `transform` 过渡；
- **动画轻量**：spinner 只动 `border-top-color` 与 `transform`，进度条只动 `transform`；
  全局已有 `prefers-reduced-motion` 兜底。

## 4. 两个 API 细节

- `rethrow`（默认 `true`）：失败时**原样抛出**，业务侧既有的 `try/catch`（回滚、写回结果区）不用改；
  设为 `false` 时由浮层单独承担报错并 `resolve(undefined)`，适合「点一下就完事」的动作，
  可避免调用处漏 `catch` 造成未处理拒绝。
- `TASK_CANCELLED`：任务执行中途弹确认框、用户点取消时返回该 Symbol，浮层立即收起，
  既不显示成功也不显示失败（`CategoryPanel` 删除分类是典型用例）。

## 6. 遗留

1. `eslint` 仍有 2 处报错，均为**并行会话遗留、非本次引入**：
   `NasImportBox.vue` 的 `nasGetAuthorization` 未使用（HEAD 版本即存在）、
   `fnos.js` 的 `timer` 赋值未使用（并行会话改动删掉了 `clearInterval(timer)` 调用）。
   未在本轮改动，避免与并行改动冲突。
2. 失败态目前固定停留 8s 后自动收起；若希望失败必须手动确认，可把 `ERROR_HOLD` 调大或改为
   `Infinity`（当前刻意保留上限，避免长期悬挂）。
3. 上传类任务目前只有「上传中 / 写库中」两段文案——浏览器未暴露分片上传进度，
   如需真实百分比要改用 `XMLHttpRequest` 的 `upload.onprogress`。
