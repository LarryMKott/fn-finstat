## Context

当前 fn-finstat 的 AI 报告只支持月度（`POST /api/ai/report`，请求体 `{month}`），且**生成即丢**——每次想看都得重新调用 DeepSeek，配额与时间成本都浪费在重复生成上。需求清单里 T-6.5（v0.6）已规划「报告升级为口径可追溯」，但用户当下要求先把报告**周期维度铺满**（月 / 季 / 半年 / 年）并加上**归档能力**，让报告成为可回看的资产而非一次性输出。

本方案落在 v0.5.3 增量版本：
- 把 AI 报告从「月度专用」泛化为「4 种周期通用」；
- 新增 `ai_reports` 表持久化归档报告，按 `(user_id, period_type, period_value)` 唯一约束做 upsert（覆盖旧报告）；
- 前端弹窗扩展为周期选择器 + 生成预览 + 归档列表 + 查看 / 删除。

## 设计要点（已与用户确认）

| 决策 | 取值 |
| --- | --- |
| `period_value` 格式 | month: `2026-09`；quarter: `2026-Q1`（Q1=1-3 月、Q2=4-6 月、Q3=7-9 月、Q4=10-12 月）；half: `2026-H1`（H1=1-6 月、H2=7-12 月）；year: `2026` |
| 归档去重 | `(user_id, period_type, period_value)` 唯一约束 upsert，重新归档覆盖旧版本 |
| 生成+归档流程 | 两步：先点「生成报告」调用 DeepSeek 出 Markdown 预览；用户审阅后点「归档」保存。查看归档不消耗配额 |

## 文件清单与改动模式

### 后端

**1. `app/utils/period.py`（扩展）**
- 新增常量 `PERIOD_TYPES = ("month", "quarter", "half", "year")`
- 新增 `valid_period(period_type, period_value)`：按类型校验（month 走 `MONTH_PATTERN`；quarter 匹配 `^\d{4}-Q[1-4]$`；half 匹配 `^\d{4}-H[12]$`；year 匹配 `^\d{4}$`）
- 新增 `period_range(period_type, period_value) -> (start, end)`：返回含当日两端 YYYY-MM-DD，复用 `month_range` / `year_window`，季/半年按首末月 `month_range` 拼装
- 新增 `prev_period(period_type, period_value) -> str`：上一周期同维标识（月→`prev_month`；季→同年前一季，Q1 回到上一年 Q4；半年同理；年→`year - 1`）
- 复用现有 `parse_month` / `next_month` / `month_range` / `year_window`，不重写

**2. `app/db/models.py`（新增模型）**
- 新增 `AIReport`：`id` / `user_id`（索引）/ `period_type`（String 8）/ `period_value`（String 10）/ `title`（String 128）/ `content`（Text，无长度上限）/ `stats_summary`（Text，存 `json.dumps(report_context())` 供溯源）/ `created_at` / `updated_at`（Float epoch，沿用 `ScheduledTask` 的时间字段惯例）
- `__table_args__ = (UniqueConstraint("user_id", "period_type", "period_value", name="uq_ai_report_scope"),)`
- 提供 `as_dict()` 返回列表/详情所需字段

**3. `app/db/migrations.py`（v4 → v5 迁移）**
- `LATEST_SCHEMA_VERSION = 5`
- 新增 `_v5_add_ai_reports_table(session)`：新表由 `init_db` 的 `Base.metadata.create_all` 幂等创建，本迁移只推进版本戳（沿用 v4 对 `scheduled_tasks` / `task_runs` / `imported_files` 的策略）
- 注册 `_MIGRATIONS[4] = _v5_add_ai_reports_table`

**4. `app/db/dao/ai_report_dao.py`（新建 DAO）**
- 参考 `app/db/dao/budget_dao.py` 的结构（同账号作用域 + 唯一键 upsert 模式）：
  - `list_all(user_id, period_type=None) -> list[dict]`：列表（不含 `content`，避免列表接口传输 Markdown）；按 `period_type` 升序、`period_value` 降序
  - `get(user_id, report_id) -> Optional[dict]`：单条详情（含 `content` + `stats_summary`）
  - `get_by_scope(user_id, period_type, period_value) -> Optional[dict]`
  - `upsert(user_id, period_type, period_value, title, content, stats_summary) -> dict`：预查 + 唯一约束兜底（用 `translate_unique_violation` 翻译并发冲突为 `ConflictError`）
  - `delete(user_id, report_id) -> bool`

**5. `app/schemas/ai.py`（新增模型）**
- `AIReportGenerateRequest`：`period_type: Literal["month","quarter","half","year"]`、`period_value: str`（缺省时由 service 按当前周期回退上月/上季/上半年/去年）
- `AIReportGenerateResult`：`period_type` / `period_value` / `title` / `report`（Markdown）/ `context`（dict，溯源数据附录）
- `AIReportArchiveRequest`：`period_type` / `period_value` / `title` / `content` / `stats_summary`（dict）
- `AIReportArchiveOut`：列表项（`id` / `period_type` / `period_value` / `title` / `created_at` / `updated_at`）
- `AIReportDetail`：`AIReportArchiveOut` + `content` + `stats_summary`
- 保留现有 `AIReportRequest` / `AIReportResult` 不动（旧 `/api/ai/report` 月度接口完全兼容）

**6. `app/services/ai_service.py`（扩展）**
- 把 `_REPORT_SYSTEM_PROMPT` 与 `_build_report_prompt` 泛化：
  - `_REPORT_SYSTEM_PROMPT` 改为「用户会提供某周期（月/季/半年/年）收支统计数据…请写一份简明的消费分析报告…500 字以内…包含总体概览、结构亮点、与上一周期变化、下一周期建议」
  - `_build_report_prompt(ctx)` 按 `ctx["period_type"]` / `ctx["period_label"]` 渲染，文案字段从「本月/上月」改为「本期/上期」
- 新增 `report_context(user_id, period_type, period_value) -> dict`：复用 `period_range` / `prev_period` 计算 start/end 与 prev_start/prev_end；其余统计（`summary` / `category_pie` / `merchant_top` / `daily_totals` 取 max_expense_day）保持现有 6 项字段，新增 `period_type` / `period_value` / `period_label`（人类可读，如「2026 年 Q3 季度」「2026 年上半年」「2026 年度」）/ `prev_period_label`
- **保留** `report_context(user_id, month)` 旧签名供 `generate_month_report` 与既有测试调用：把旧实现改为转发到新签名（`period_type="month"`），避免重复代码
- 新增 `generate_report(user_id, period_type, period_value) -> dict`：返回 `{period_type, period_value, title, report, context}`；`title` 由 `period_label` + 「消费分析报告」生成
- 旧 `generate_month_report(user_id, month=None)` 转发到 `generate_report`，保持响应字段 `{month, report}` 不变（兼容旧测试）
- 新增归档服务函数（薄封装 DAO + 校验）：
  - `archive_report(user_id, period_type, period_value, title, content, stats_summary) -> dict`：校验 `period_type/value` 合法性，调 `AIReportDAO.upsert`
  - `list_archived(user_id, period_type=None) -> list[dict]`
  - `get_archived(user_id, report_id) -> dict`（不存在抛 `BizError`）
  - `delete_archived(user_id, report_id) -> bool`

**7. `app/api/ai.py`（新增路由）**
- 旧 `POST /api/ai/report`（月度）**保持不变**，不动签名
- 新增 `POST /api/ai/report/generate`：`AIReportGenerateRequest` → `AIReportGenerateResult`（普通用户可调用，生成预览不落库）
- 新增 `POST /api/ai/report/archive`：`AIReportArchiveRequest` → `AIReportArchiveOut`（普通用户可归档自己的报告）
- 新增 `GET /api/ai/report/list?period_type=...`：→ `list[AIReportArchiveOut]`（只看自己）
- 新增 `GET /api/ai/report/{report_id}`：→ `AIReportDetail`
- 新增 `DELETE /api/ai/report/{report_id}`：→ `{ok: bool}`
- 全部经 `get_gateway_user` 注入 `user_id`，DAO 层强制过滤（NFR-004 数据隔离底线）

### 前端

**1. `frontend/src/api/ai.js`（新增函数）**
- `aiGenerateReport(periodType, periodValue)` → `POST /api/ai/report/generate`，timeout 90s
- `aiArchiveReport({periodType, periodValue, title, content, statsSummary})` → `POST /api/ai/report/archive`
- `aiListArchived(periodType?)` → `GET /api/ai/report/list`
- `aiGetArchived(id)` → `GET /api/ai/report/{id}`
- `aiDeleteArchived(id)` → `DELETE /api/ai/report/{id}`
- 保留 `aiMonthReport(month)` 不动

**2. `frontend/src/components/AIReportModal.vue`（重构交互）**
- 把单月份选择器改为「周期类型 + 周期值」双输入：
  - 类型下拉：月度 / 季度 / 半年度 / 年度
  - 值选择器按类型切换：月→`<input type="month">`；季→年+季下拉（Q1-Q4）；半年→年+H1/H2 下拉；年→`<input type="number">`
- 顶部按钮：「生成报告」（生成预览，不落库）+ 「归档」（保存当前预览到 `ai_reports`）
- 弹窗底部新增「归档报告列表」分区：
  - 列表项：标题 + 周期标签 + 归档时间 + 「查看」/「删除」按钮
  - 「查看」直接从归档读取（不消耗配额），渲染到主预览区
  - 「删除」二次确认后调 DELETE
- 列表按周期类型分组或按时间倒序，用 `--color-divider` 分隔，沿用 `--color-*` 语义层（NFR-010）

**3. `frontend/src/components/DashboardPanel.vue`（按钮文案）**
- 「AI 月度报告」按钮文案改为「AI 报告」（功能范围已扩为 4 种周期）
