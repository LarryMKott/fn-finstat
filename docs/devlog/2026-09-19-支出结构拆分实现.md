## 1. 口径（全部为真实账单统计，不含预测成分）

- 窗口 = 近 **6** 个完整自然月（比现金流预测的 3 个月更长，固定/弹性判定更稳）；
- **必选项（固定支出）**：复用 T-6.4 现金流预测的固定项识别规则——同商户在窗口内
  每个完整月都出现、月度合计波动 ≤ 25%（`_identify_fixed_items` 直接复用）；
- **可砍项（弹性支出）**：其余支出按商户聚合，月均 = 窗口合计 ÷ 月数，降序排列；
- 汇总：固定 / 弹性月均合计与固定占比（fixed_pct）；账本维度可选
  （复用 forecast_rows 的 ledger 过滤，与预算建议同口径）。

## 2. 实现

- `forecast_service.expense_structure(user_id, today, ledger_id)`：
  `forecast_rows` 取窗口内支出窄列 → `_identify_fixed_items` 判定必选项 →
  其余按商户聚合为可砍项；商户名空串归入「（未填商户）」。
- `GET /api/forecast/expense-structure?ledger_id=`（挂在 forecast 路由，
  与固定项识别同域）。
- 前端：现金流预测卡片内新增「支出结构」区块——必选 / 可砍占比双条、
  两列清单（必选项含月度金额；可砍项月均降序、超出 8 项折叠提示）、
  判定口径脚注；随预测加载同窗口刷新。
