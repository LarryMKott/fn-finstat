## 1. 数据模型（schema v12）

- `loans`：user_id（归属账号）/ direction（lend=借出即应收，borrow=借入即应付）/
  counterparty（对方）/ principal（本金）/ loan_date / due_date（可选）/
  note / status（open 进行中，settled 已结清）/ created_at。
- `loan_payments`：loan_id / amount / pay_date / note——一笔借贷可多次还款，
  合计即已还金额。
- 与流水不强制关联（计划要求）；不参与收支统计，台账只记资金往来进度。

## 2. 「还清即结项」推导

status 由服务层按还款合计自动推导并落库：repaid >= principal → settled，
删除还款记录后合计不足 → 回到 open；编辑本金同样重推导。不提供手动改状态
（口径唯一，避免「没还清却标结清」的脏状态）。

## 3. 接口（/api/loans，数据按账号隔离）

`GET ""` 台账总览（receivable 应收未收合计 / payable 应付未还合计 + 逐条
进度含 repaid/remaining/payment_count）；`POST ""` 登记；`PUT /{id}` 更新
（本金变化后重推导状态）；`DELETE /{id}` 连同还款记录一并删除；
`GET|POST /{id}/payments` 还款明细与登记；`DELETE /{id}/payments/{pid}` 删还款。
错误码新增 **490xx 借贷域**（LOAN_INVALID=49001 / LOAN_NOT_FOUND=49002）。

## 4. 备份（format_version 4 → 5）

- 新增 loans / loan_payments 节；loans 保留 id；

  `loan_payments.loan_id` 据此重映射；映射不到的还款按孤儿计数跳过。
