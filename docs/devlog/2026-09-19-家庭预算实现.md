## 1. T-7.3 家庭预算

### 1.1 数据模型（schema v10）

`budgets.family_id INTEGER NULL`（索引 `ix_budgets_family_id`）：NULL = 个人预算
（T-7.1 行为完全不变，升级零回填）；非空 = 家庭预算。迁移 `_v10_add_family_budget`
只需加列 + 索引——家庭预算行的去重复用既有唯一键
`(user_id, ledger_id, month, category)`：

- 家庭行的 `user_id` 写**合成属主** `constants.family_scope_user(family_id)`
  （即 `"family:3"`），保证「家庭内 (月份+分类) 唯一」且与创建者本人的个人预算
  同月同分类**共存不撞键**（此前若直接用创建者 user_id，个人预算行会挡住家庭
  预算行落库——这是本设计规避的核心冲突）；
- `ledger_id` 列 NOT NULL，家庭预算不按账本维度、统一落默认账本占位（家庭口径
  = 成员各账本之和，天然跨账本）；
- 真实 user_id 是纯数字串，`family:` 前缀永不冲突。

### 1.2 后端

- `BudgetDAO`：`list_family` / `upsert_family`（预查 + 唯一约束兜底转
  ConflictError）/ `delete_in_family`（限本家庭）/ `delete_family_budgets`
  （解散清空）/ `category_amount`（current_budget 同口径取数）。
- `StatDAO.category_pie_for_users`：多成员合并的分类支出（IN 成员集合，
  与 category_pie 同口径：仅支出、排除回收站）。
- `budget_service`：抽出 `_validated_budget_payload` 共享校验；新增
  `family_overview`（进度 = 全体成员支出之和，返回结构与个人总览一致）、
  `upsert_family_budget` / `delete_family_budget`（家庭管理员校验收口）。
- `family_service`：解散家庭（管理员解散 + 最后一人退出自动解散两条路径）
  均先清家庭预算再删家庭，不留孤儿行；成员各自数据不受影响。
- 接口（`/api/family/budgets`，进家庭路由而非预算路由——权限模型是家庭内部
  角色）：`GET ?month=` 全员可读进度；`PUT` / `DELETE /{id}` 仅家庭管理员；
  误传 `ledger_id` 明确 400。
- 备份恢复（format_version 2 → **3**）：budgets 行携带 family_id；恢复时按
  邀请码重映射到新家庭 id 并把 user_id 改写为合成属主，映射不到家庭的行按
  孤儿跳过计入 skipped；v2 备份缺 family_id 时按个人预算恢复。

### 1.3 前端

- 家庭页新增「家庭预算」卡片：全员可见进度条（已用/预算/余 或 超支红标），
  管理员可见添加/删除表单；月份与家庭汇总共用同一月份选择器。
- `api/family.js` 新增三个端点封装。

## 2. T-7.1 评审遗留收口

### 2.1 流水 / 资产快照可移动账本

- `BillUpdate` / `AssetSnapshotUpdate` 增 `ledger_id`：传值走
  `ledger_service.resolve_write` 校验（不存在 → 404），**显式 null 与未传
  等价**（不迁移）——asset 侧从 `exclude_unset` 原始入参取值（此前经
  `v is not None` 过滤会丢掉 null 键，纯 null 更新会误报 404，已修）；
  asset 纯 null/空体更新改为回当前快照而非 404。
- `BillModal` 编辑弹窗新增「账本」下拉（默认账本带标注），新建与编辑共用。

### 2.2 对话式查账与预算建议接入账本口径

- **NL 查账**：`POST /api/nl-query` 请求体增 `ledger_id`（界面账本切换器
  上下文）。设计上它是**界面口径而非语言意图**——不进 LLM 翻译的 spec、
  不占白名单，由请求参数直传 `_execute`（`nl_aggregate` 本就支持，
  `nl_detail_rows` 补齐同参数）；答案文本点名账本（「账本「X」，…」）保持
  口径透明；显式传不存在的账本 id 报 404 而非静默空结果。
- **预算建议**（`budget_suggestions`）：增 `ledger_id` 参数。建议支出窗口
  与 `current_budget` 现在**严格同口径**：不传 = 全部账本（current_budget
  为各账本同月同分类预算合计，替代原 `get_by_scope` 落默认账本的口径错位），
  传账本 = 均限定该账本。`forecast_rows` 本就支持 ledger 过滤，直接贯通。
  现金流预测维持全账号口径不变（余额投影是账号级概念，账本只是视图分组），
  计划遗留清单中相应销项。

## 3. 顺带修复

备份恢复的 **replace 模式会丢光全部分类**：`export_backup` 把 categories
导出为纯字符串数组，而 `_clean_row` 对非 dict 行一律判坏行跳过（分类仅靠
流水引用被间接补建）。修复：v3 格式改为对象数组 `[{"name": ...}]`，恢复端
同时兼容 v2 字符串数组与 v3 对象数组。
