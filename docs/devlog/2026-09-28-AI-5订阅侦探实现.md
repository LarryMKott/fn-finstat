## 交付内容（S/M，零 AI 成本，纯只读统计）

`forecast_service.subscriptions()` + `GET /api/forecast/subscriptions`（与
expense-structure 同为只读聚合口径，`ledger_id` 可选），前端看板「现金流预测」
区新增订阅侦探卡片。复用固定项识别的解析口径（`_parse_rows` /
`_fixed_amount_day` / `FIXED_AMOUNT_BAND`），**但判定刻意比固定项宽松**：

| 维度 | 固定项识别（现金流/T-1.5） | 订阅侦探（AI-5） |
| --- | --- | --- |
| 窗口 | 3 ~ 6 个完整月 | **12 个完整月**（`SUBSCRIPTION_WINDOW_MONTHS`） |
| 出现要求 | 每月都出现 | 窗口内出现 **≥ 3 个月**（`SUBSCRIPTION_MIN_MONTHS`） |
| 金额要求 | 带宽 ≤ 25% 才算 | 不设门槛（涨价/波动正是要暴露的信号） |

放宽的理由：**涨价月天然破坏带宽**（按固定项规则，涨价的订阅会从必选项里
整个消失）、断缴一个月的真实订阅也不该整项消失。订阅的时间线、涨价、僵尸
三个维度各自独立判定：

1. **订阅时间线**：按商户聚合月度合计，给出月均（非零月中位数，抗单月
   尖峰）、最近月金额、出现月数、**连续扣费月数**（自窗口末往前数）、
   首次出现月份、常规扣款日、最常见分类（展示提示）；
2. **台阶涨价检测**（`_detect_price_step`）：存在切分点使后段**每个月**
   合计 ≥ 前段中位数 × `SUBSCRIPTION_PRICE_STEP_FACTOR(1.2)`——「每月都
   不回落」保证台阶被保持，**单月尖峰（年费/退款冲正）不误报**；命中标出
   起始月与前后水平（to 取后段中位数）；
3. **疑似僵尸订阅**：整个窗口每月都扣费 + 波动 ≤ 25% + 没涨过价 →
   提示复核是否还需要（连续满一年未审视的订阅）。

月合计 = 各订阅月均之和；**占收入比** = 月合计 ÷ 窗口内非零月收入中位数
（无收入流水如实返回 `null`，不虚构）。

## 接口与前端

- 响应结构：`window` / `monthly_total` / `income_monthly` / `income_pct` /
  `caliber`（min_months、price_step_factor、band_pct，前端口径行据此渲染，
  与 expense-structure 的 band_pct 同模式）/ `subscriptions[]` /
  `flag_counts`。空商户名流水不参与（订阅必须可归因到商户）。
- 前端 `ForecastSection.vue`：支出结构块下方新增「订阅侦探」块（随预测
  同窗口并行加载，`silent` 静默模式），每行 = 商户 + 涨价/僵尸徽标（悬停
  看涨价详情）+ 月均与连续月数；无订阅时不渲染整块。

## 测试

`tests/services/test_subscriptions.py`（6 例）：整年稳定扣费判僵尸并给全
时间线；出现 < 3 个月与无商户名跳过；台阶涨价命中起始月/前后水平且非僵尸
（streak 按出现计为 12）；单月尖峰不误报且中位数不被抬高；断缴几个月不
整项消失、连续月数从窗口末往前数；月合计/占收入比/无收入留空。
