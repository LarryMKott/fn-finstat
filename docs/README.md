## 4. 命名与元信息约定

### 4.1 命名规则

| 类别 | 规则 | 示例 |
| --- | --- | --- |
| 现行规范 / 方案类 | `<主题>.md`，主题用中文，不用日期 | `界面设计方案.md` |
| 开发日志类 | `devlog/YYYY-MM-DD-<主题>.md`，日期取**创建日** | `devlog/2026-09-13-功能扩展开发计划.md` |
| 图片素材 | `images/<类别>-<名称>.png`，类别用中文短词 | `images/截图-统计看板.png` |
| 历史存档 | 移入 `docs/archive/`，文件名前加版本前缀 | `archive/v0.1-项目需求文档.md` |

**禁止**在 `docs/` 根目录散落图片或其他二进制素材——一律进 `docs/images/`。

### 4.2 元信息头（现行文档必填）

每份现行文档标题下方应紧跟一张元信息表，字段与取值如下：

```markdown
| 项 | 内容 |
| --- | --- |
| 文档版本 | v1.0 |
| 制定日期 | YYYY-MM-DD |
| 文档状态 | <状态取值> |
| 关联文档 | 用反引号写出相对路径 |
| 索引 | `docs/README.md` |
```

**状态取值集**（只能用这几个，避免状态语义漂移）：

| 状态 | 含义 |
| --- | --- |
| 待确认 / 待评审 | 内容已完成，等决策 |
| 已确认 | 通过评审，可作为依据 |
| 实现中 | 正在按此文档推进 |
| 已落地 | 文档描述的内容已实现 |
| 历史基线 | 曾为基线，现已被取代，不作为现状依据 |
| 已废弃 | 明确停用，仅留档 |

### 4.3 交叉引用规则

- 文档间引用一律用**仓库相对路径**并加反引号，如 `` `docs/界面设计方案.md` ``；
- 内嵌图片用**相对本文件的路径**，如 `![图标验证图](images/图标双模式对照.png)`；
- 需求编号（`REQ-<域>-<序号>`）**一经分配永不复用**；范围变化新增编号，并在原条目标注「被 REQ-XXX 取代」。
