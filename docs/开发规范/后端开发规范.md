# 后端开发规范

> 适用目录：`app/`
> 配套：[Git提交规范.md](Git提交规范.md) · [前端开发规范.md](前端开发规范.md) · [重构说明.md](../重构说明.md)
> 与 `app/core/`、`app/db/`、`tests/conftest.py` 的实际实现严格对应

## 1. 技术栈与分层

| 项 | 选型 |
| --- | --- |
| 框架 | FastAPI（同步端点为主）+ Uvicorn |
| ORM | SQLAlchemy 2.x（ORM 风格） |
| 数据库 | **三方言**：SQLite（默认）/ MySQL / PostgreSQL |
| 校验 | Pydantic v2 |
| 测试 | pytest（`pytest.ini` 把 `app.*` 的 DeprecationWarning 升级为 error） |
| 静态检查 | `ruff check app cmd scripts tests --select F,E9` |
| 格式化 | black（`pyproject.toml`，line-length 88，**已接入 CI 门禁**） |

**依赖方向（单向，禁止反向）**：

```
core ← utils ← parsers ← db(dao) ← services ← api ← main
```

| 层 | 目录 | 职责 | 禁止 |
| --- | --- | --- | --- |
| core | `app/core/` | 错误码、异常族、请求上下文、中间件、异常→HTTP 适配 | 依赖任何业务层 |
| utils | `app/utils/` | 纯函数（金额/周期/筛选/文件头） | 运行期依赖 Web 框架、写库 |
| parsers | `app/parsers/` | 账单解析，平台注册表 `PARSERS` 单一来源 | 反向依赖 services |
| db | `app/db/` | 引擎/迁移/ORM/DAO；DAO 静态方法 + `user_id` 隔离 | 依赖 services / api |
| services | `app/services/` | 业务校验与流程，异常语义化 | **抛 HTTPException、import fastapi** |
| api | `app/api/` | 参数校验、依赖注入、`ok()` 包装 | 业务逻辑、写库 |

**铁律**：`db` / `utils` / `parsers` / `services` **运行期不得 import fastapi**。
（`utils/file_utils.py` 的 `UploadFile` 仅作 `TYPE_CHECKING` 标注，属允许的例外。）

## 2. 接口契约

### 2.1 响应结构

除**文件下载端点**（导出 xlsx/csv、备份 JSON、日志，返回二进制）外，所有接口返回：

```jsonc
{ "code": 0, "msg": "ok", "data": <业务数据> }          // 成功 2xx
{ "code": 40002, "msg": "交易单号已存在", "data": null } // 失败 4xx/5xx，data 恒为 null
```

路由用 `response_model=ApiResponse[...]` 声明，返回时 `ok()` 包装：

```python
@router.get("/list", response_model=ApiResponse[PageResult[BillOut]], summary="分页查询账单流水")
def list_bills(user: CurrentUser, filters: FiltersDep, page: int = Query(1, ge=1)):
    total, items = bill_service.list_bills(user.user_id, filters.as_dict(), page, ...)
    return ok(PageResult(total=total, page=page, page_size=page_size, items=items))
```

`ApiResponse` / `PageResult` / `ok` 定义在 `app/schemas/common.py`。

### 2.2 错误码

**所有错误码必须登记在 `app/core/errors.py::ErrorCode`**，按领域分段：

| 段 | 领域 |
| --- | --- |
| 0 | 成功 |
| 100xx | 通用（参数 / 权限 / 不存在 / 冲突 / 上传限制） |
| 400xx | 账单流水 |
| 410xx | 消费分类 |
| 420xx | 账单导入 / 解析 |
| 430xx | NAS 目录导入 |
| 440xx | 预算 |
| 450xx | 资产快照 |
| 470xx | 设置 / 数据库 |
| 480xx | 智能分类（AI） |
| 50000 | 服务器内部错误 |

新增领域**新开一段**，不复用其他领域的号段。

### 2.3 异常协议

**服务层与 DAO 层只抛 `BizError` 子类，路由层不写 `try/except` 翻译**，由全局异常处理器统一转换。

| 异常 | HTTP | 用途 |
| --- | --- | --- |
| `ValidationError` | 400 | 参数/业务规则不合法 |
| `PermissionDeniedError` | 403 | 权限不足 |
| `NotFoundError` | 404 | 资源不存在 |
| `ConflictError` | 400 | 数据冲突（唯一约束） |
| `UploadTooLargeError` | 400 | 上传超限 |
| `ImportParseError` | 400 | 账单解析失败（**文件内容问题**） |
| `ConfigError` | 400 | 配置错误（message 含操作指引） |
| `EnvironmentError_` | 500 | 运行环境故障（驱动缺失等） |

> **区分 `ImportParseError` 与 `EnvironmentError_`**：前者是用户文件问题，后者是环境故障。不要把环境故障伪装成用户输入错误，否则用户会反复改文件却永远修不好。

`msg` **面向用户**，前端 `toast(err.message)` 直接展示。禁止把堆栈、SQLAlchemy 细节、文件绝对路径写进 `msg`。

## 3. 各层写法

### 3.1 DAO（`app/db/dao/`）

- **入口是 `class XxxDAO` + `@staticmethod`**，不实例化
- 用 `with get_db() as session:`（正常提交、异常回滚）
- 所有查询**必须带 `user_id` 条件**做账号隔离
- 返回 `dict`（经 `model.as_dict()`），不泄漏 ORM 对象
- 排序字段必须经**白名单映射**到模型列，禁止把用户输入直接拼进 `ORDER BY`
- 列表接口导出分页上限常量（如 `EXPORT_LIMIT = 100_000`、`BATCH_LIMIT = 1000`），供服务层校验

```python
class BillDAO:
    @staticmethod
    def insert_many(records: list[dict], user_id: str) -> int:
        rows = [_normalize(r, user_id) for r in records]
        with get_db() as session:
            before = session.scalar(select(func.count()).select_from(Bill))
            insert_ignore_rows(session.connection(), Bill.__table__, rows)
            session.flush()
            after = session.scalar(select(func.count()).select_from(Bill))
        return after - before
```

**并发安全：预检查 + 唯一约束兜底**（并发下预检查可能漏过，唯一约束是最终防线）：

```python
with translate_unique_violation("交易单号已存在", code=ErrorCode.BILL_TX_ID_DUP):
    session.add(Bill(**values))
```

**三方言差异统一封装在 `app/db/engine.py`**，不要在业务代码里 `if dialect == "mysql"`：

| 需求 | 用 |
| --- | --- |
| 批量插入跳过冲突 | `insert_ignore_rows(conn, table, rows)` |
| IN 子句切片 | `in_chunks(ids)`（默认 900，规避 SQLite 绑定变量上限） |
| 唯一约束冲突判定 | `translate_unique_violation(...)` / `is_unique_violation(exc)` |

> **不用驱动的 `rowcount` 判断插入条数**——SQLite/PG 可能返回 -1。用事务内 `COUNT` 差值。

### 3.2 服务层（`app/services/`）

**类承载业务逻辑，模块级同名函数作为薄封装**（`class BillService` + `def list_bills(...)`），保证既有调用方零改动。

职责边界：

- ✅ 入参业务校验（收支类型、账户类型、金额正数）、字段归一化、`user_id` 归属
- ✅ 把 DAO 的 `IntegrityError` 转为 `ConflictError` / `ValidationError`
- ❌ 不写 SQL、不 `commit`（事务由 `get_db()` 上下文管理）
- ❌ 不 import fastapi、不感知 HTTP

**更新字段必须走白名单**，防止越权改字段：

```python
_UPDATE_FIELDS = {"tx_time", "account", "tx_type", "merchant", "amount", "category", "remark", ...}
```

筛选条件用 `@dataclass(frozen=True)` 承载（如 `BillFilters`），避免多参数位置错位。

### 3.3 路由层（`app/api/`）

- 每个业务域一个 router，声明 `prefix` + `tags`，**挂 `dependencies=[Depends(request_db_session)]`**
- 端点只做：依赖注入 → 调服务 → `ok()` 包装。**不写业务逻辑、不直接写库**
- 身份注入用签名别名：`user: CurrentUser`、`_: AdminUser`（替代重复的 `Depends(...)`）
- 所有 `Query(...)` / `Body(...)` 参数**必须写 `description`**（生成 OpenAPI）
- 共用查询参数抽成依赖函数 + `Annotated` 别名（参考 `FiltersDep`）

新建 router 后**必须**在 `app/main.py` 的 `_prefixes` 循环中注册——路由要同时挂载在根路径与向导前缀下，漏挂会导致自定义前缀下 404。

### 3.4 Schema 层（`app/schemas/`）

- 按业务域分文件，与 api / services 同名
- 输出模型提供 `from_model(dict) -> XxxOut`，或由服务层返回 dict 后经 `response_model` 转换
- **长度等约束的常量单一来源**（如 `TAGS_MAX_LENGTH` 定义于 `app/db/models.py`、`CATEGORY_NAME_MAX_LENGTH` 定义于 `app/schemas/category.py`），校验处共享同一常量，禁止重复写数字

## 4. 身份、隔离与权限

### 4.1 身份来源

身份由飞牛网关通过 **`X-Trim-Userid` / `X-Trim-Username` / `X-Trim-Isadmin` / `X-Trim-Theme`** 请求头注入，解析统一在 `app/core/context.py::gateway_user_from_headers`。

> ⚠️ **这些头被无条件信任，不做来源校验。** 因此应用绝不能直接暴露在不可信网络：
> - fnOS 网关模式：`cmd/main` 以 `uvicorn --uds` 启动，只绑 Unix Socket；**缺失身份头的请求一律 401（code=10006）拒绝**，设备上排障需自带身份头或临时开 `FNOS_ALLOW_HEADERLESS=1`（默认关闭）
> - 独立部署：`config.HOST` 默认绑 `127.0.0.1`，并有来源校验中间件兜底（Host 白名单防 DNS rebinding、写方法 Origin 同源防 CSRF，见 `core/middleware.py::SourceGuardMiddleware`）
>
> 前提被破坏，攻击者伪造两个头即可提权为管理员（可导出全量备份、覆盖恢复数据、改数据库配置、下载日志）；`HOST` 改为非回环地址时启动日志会告警信任面扩大。

### 4.2 数据隔离

**普通接口的数据隔离由服务层按 `user_id` 过滤保证**，不依赖权限中间件。所有 DAO 查询条件必须带 `user_id`。

### 4.3 管理员权限（双层防御）

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 第一层 | `core/permissions.py` 的 `_ADMIN_RULES` 中间件 | 路由分发前拦截，**默认拒绝管理面**，漏挂守卫也兜底 |
| 第二层 | `deps.require_admin` / `AdminUser` | 路由守卫，提供 OpenAPI 语义的 403 |

**新增管理员接口必须同时更新两处，并补一条测试**：

```python
# 1. core/permissions.py
_ADMIN_RULES = [
    ...
    ({"PUT"}, re.compile(r"^/api/xxx/config$")),
]

# 2. api/xxx.py
@router.put("/config", response_model=ApiResponse[None], summary="保存配置")
def save_config(_: AdminUser, payload: XxxConfigIn): ...
```

两层文案必须一致（都指向 `ADMIN_ONLY_MSG`），前端无需区分拦截来自哪层。

> 无网关身份头（`user_id` 为空串）的处理**按运行形态区分**：独立部署/本地开发 = 单机唯一用户**全量放行**；fnOS 网关模式 = 未认证，**一律 401（code=10006）**，排障可临时开 `FNOS_ALLOW_HEADERLESS=1` 恢复放行（两层判定见 `core/permissions.py::access_rejection` 与 `deps.require_admin`，必须同步修改）。
>
> ⚠️ **独立部署放行规则的安全前提是 4.1 节的网络隔离与来源校验中间件。** 空身份等同唯一用户（含管理面），任何改变监听地址、增加反代、暴露端口的改动都必须重新评估此规则。

## 5. 数据库与迁移

### 5.1 会话管理

- 业务代码统一 `with get_db() as session:`，**不要自己 `sessionmaker`**
- 路由级共享会话由 `deps.request_db_session` 注入（同一请求内多次 DAO 调用复用同一会话）
- **`request_db_session` 必须是 `async` 生成器**：FastAPI 对同步依赖在线程池副本中执行，副本里 `set` 的 ContextVar 不会回传请求任务，端点线程读不到，DAO 侧无法复用会话
- 事务边界不变：仍由每个 `get_db` 块自行提交/回滚

### 5.2 Schema 迁移

- 迁移函数登记在 `app/db/migrations.py::_MIGRATIONS`（`vN → vN+1`），启动时按序应用
- **每个迁移必须幂等**：MySQL 的 DDL 隐式提交、无法回滚，中断重启会重跑
- 每个迁移独立事务，完成后立即写版本戳（`set_schema_version`）
- 新增迁移后**同步更新 `LATEST_SCHEMA_VERSION`**，并补 `tests/test_migration_vN.py`
- 跨方言 DDL 差异用 `_mysql_column_exists` 之类辅助函数处理（MySQL 无 `ADD COLUMN IF NOT EXISTS`）

### 5.3 连接配置

生效优先级：向导环境变量 > `db_config.json` > 通用环境变量 > 默认本地 SQLite。

配置写入用 `_atomic_write_text`（先写临时文件再 `os.replace`）——直接 `write_text` 时并发会读到半截 JSON 并静默降级；配合 `_CONFIG_WRITE_LOCK` 做进程内互斥。

## 6. 异步与共享状态

- 端点以**同步 `def`** 为主（SQLAlchemy 同步 ORM）。只有确实需要 `await`（async 依赖、异步 IO）时才写 `async def`
- 跨线程共享状态（备份、迁移、恢复）**必须互斥**——历史上迁移与备份恢复曾各用一把锁而互相踩踏
  - 新增全局性操作时**复用已有锁**，不要新建独立锁
  - 进程内共享可变状态用 `threading.Lock` 保护（参考 `_EngineState`）
- 请求级上下文（请求 ID、请求会话）用 `ContextVar`，**必须成对 `set`/`reset`**：

```python
token = bind_request_session(session)
try:
    yield session
finally:
    unbind_request_session(token)   # 必须复位，防跨请求串会话
```

## 7. 安全

| 要求 | 说明 |
| --- | --- |
| **路径脱敏** | 不把服务器绝对路径（账单目录等）回传前端；解析异常回显前先脱敏 |
| **不跟随重定向** | 外部请求（AI 调用）禁用重定向跟随，防 SSRF |
| **排序白名单** | `ORDER BY` 字段白名单映射，禁止拼接用户输入 |
| **字段白名单** | 更新接口只允许改白名单内字段 |
| **上传限制** | 统一用 `config.MAX_UPLOAD_SIZE` / `MAX_UPLOAD_SIZE_MB`（文案三处共用） |
| **敏感信息不入日志** | 记录异常用 `logger.exception`，对外 `msg` 只给通用文案 |
| **临时目录清理** | 打包/下载产生的暂存目录用后即清 |

## 8. 日志与观测

- 用 `logging.getLogger(__name__)`，**禁止 `print`**
- 未预期异常由全局处理器 `logger.exception` 记录完整堆栈（带请求 ID，设置页「运行日志」可查），**对外只返回「服务器内部错误，请稍后重试」**
- 日志文件：单文件 10MB、保留 3 个备份；`_setup_logging` 按「目标 logger 是否已挂同路径 handler」防重入（**不能只靠模块级标志**，`uvicorn --reload` 会重新执行模块导致 handler 重复挂载、日志逐行翻倍）
- 请求 ID 与耗时由观测中间件附加；未处理异常路径需手动补安全头与 `X-Request-ID`（该处理器在中间件之外，响应不再经过中间件）

### 9.2 编写要求

- 不依赖外部网络；外部调用（AI）必须有未配置密钥时静默跳过的路径

## 10. 命名与常量

- 模块 `snake_case`；DAO 类 `XxxDAO` + 静态方法；服务类 `XxxService` + 模块级薄封装函数
- 常量**全大写**且**单一来源**，禁止多处重复定义同一数字/字符串
- 周期计算一律 `app/utils/period.py`；金额取整一律 `app/utils/amount.py::round2`；附件下载头一律 `app/utils/file_utils.py::content_disposition`
- 中文注释解释**为什么**；模块顶部写 docstring 说明职责与约定

## 12. 新增业务域顺序

1. `app/db/models.py` 加 ORM 模型（如需要）→ 需要时加迁移
2. `app/db/dao/xxx_dao.py` 写 `XxxDAO`（静态方法 + `user_id` 隔离 + 白名单）
3. `app/schemas/xxx.py` 定义入参/出参模型
4. `app/services/xxx_service.py` 写 `XxxService` + 模块级薄封装
5. `app/api/xxx.py` 写 router（挂 `request_db_session`，参数带 `description`）
6. `app/main.py` 注册 router（注意两个前缀）
