## 四、实测验证结论（2026-09-26）

以下结论来自**对运行实例的真实 HTTP 请求**，非静态代码推断。复现脚本见附录。

| 编号 | 结论 | 证据 |
| --- | --- | --- |
| ✅ M1-1 | 管理面越权**已正确拦截** | `GET /api/settings/logs` + 普通用户 → `403 {"code":10002,"msg":"该操作仅限管理员账号"}` |
| ✅ M1-3 | 普通用户恢复数据**已拦截** | `POST /api/settings/restore` → `403` |
| ✅ M1-4/6 | 全局配置写**已拦截** | `PUT /api/nas/config` → `403` |
| ⚠️ M1-7 | **伪造 `X-Trim-Isadmin: true` 即可成管理员** | 登录用户附加 `X-Trim-Isadmin: true` → `GET /api/settings/logs` 返回 `200` 且含全量日志。**这是设计契约**（信任网关），风险落在部署边界：一旦应用被直连（`HOST` 非回环 / 网关被绕过）即整体提权 |
| ✅ M15-3 | Token **fail-closed** 正确 | 无效 Token（`Bearer ffk_deadbeef` / `X-Api-Token: garbage`）→ `401 {"code":10006,"msg":"无效的 API Token"}`，未降级为匿名 |
| ✅ M9-1 | CSRF **已拦截** | `POST /api/bills` + `Origin: http://evil.com` → `403 请求来源不受信任` |
| ✅ M14-1 | Host 白名单**生效**（`HOST=127.0.0.1`） | `Host: evil.com` → `403`；`Host: 127.0.0.1` → `200` |
| ❌ **M14-2** | **`HOST=0.0.0.0` 时 Host 白名单整体失效** | 项目 `.env.dev` 设 `HOST=0.0.0.0` → `HOST_IS_WILDCARD=True` → 代码跳过 Host 校验；实测 `Host: evil.com` → `200`。**DNS Rebinding 可绕过同源策略读取接口数据** |
| ❌ **M5-2/3** | **SSRF 可达内网与云元数据端点** | `send_webhook` 实测：`file://`/`gopher://`/`dict://` → **已拒绝**；但 `http://169.254.169.254/...` → `TimeoutError`（**已发起连接**，仅超时未拦截）、`http://localhost:8090/...` → `HTTP 502`、`http://127.0.0.1:6379/` → `HTTP 502`。**无内网地址黑名单**，可做端口扫描与服务探测 |
| ✅ M5-5 | 出站**不跟随重定向** | 实测 302 场景返回 `HTTP 302` 失败，未跳转 → `_NoRedirect` 正确 |
| ✅ M10-1 | **无宽松 CORS** | 全部响应无 `Access-Control-Allow-Origin` |
| ✅ M11-1 | 重定向目标为常量 | `RedirectResponse(url=f"{PREFIX}/")`，`PREFIX` 来自向导配置，非用户输入 |
| ✅ M8-1/3 | **AI 报告 `v-html` 不可注入**（重点澄清） | 实测 `escapeHtml` 先于行级替换执行 → `**<img src=x onerror=alert(1)>**` 输出 `<strong>&lt;img src=x onerror=alert(1)&gt;</strong>`；`</strong><img ...>` 亦被完整实体化。**代码注释「先转义 HTML 再做替换」属实** |
| ⚠️ M8-9 | 无 CSP | 响应头仅有 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`；无 CSP/HSTS/X-Frame-Options（X-Frame 因 fnOS iframe 嵌入**刻意不加**，属已知取舍） |
| ⚠️ M7-12 | 日志文件权限需设备侧核验 | Windows 环境下 `harden_perms` 静默跳过；须在 NAS（POSIX）上核 `app.log` 及其轮转文件为 `0600` |
| ⚠️ M4-4 | 动态表名 SQL 需人工回溯 | `app/db/copy.py:91` 存在 `text(f"... FROM {table}")` 形态，**须回溯 `table` 是否可被请求参数控制**（本次未定论，列为待测） |

## 五、测试执行说明


**通用请求模板**

```bash
# 普通用户
-H "X-Trim-Userid: 10002" -H "X-Trim-Username: u2"
# 管理员
-H "X-Trim-Userid: 10001" -H "X-Trim-Isadmin: true"
# API Token（只读）
-H "Authorization: Bearer ffk_<32位hex>"
```

**注意事项**

1. 项目无账号/口令体系，**JWT 与弱口令相关的经典用例以 N/A 标记**，改测等价的不透明 Token 与网关头。
2. `HOST` 绑定非回环时应用启动会打印醒目告警——**该告警本身就是 M14 的判定依据之一**。
3. 越权类用例必须用**两个真实存在的账号**，并预先在 `UA` 下构造数据，否则无法区分「无数据」与「被隔离」。
4. 网关模式（`IS_FNOS=1`）下 `SourceGuardMiddleware` **整体跳过**（Host 白名单 + Origin 校验均不生效），CSRF/CSRF 用例须明确标注测试形态。
5. 所有注入类用例以**无害验证**为准（`alert`/`sleep`/`SELECT 1`），禁止在生产 NAS 上执行破坏性 Payload。
