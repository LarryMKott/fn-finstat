## 1. 架构总览

```
┌─ frontend/（Vue 3 SFC + Vite，无 TS）
│   main.js → App.vue（外壳 + tab 导航）
│     ├─ api/          接口层：client.js 统一封装 + 按业务域端点模块（唯一出口）
│     ├─ composables/  组合式函数：useChart（图表生命周期）、useConfirm（确认弹窗）
│     ├─ utils/        共享工具：format / datetime / constants / charts / chartTheme
│     ├─ components/   面板与弹窗；大面板按业务域拆子组件（settings/ import/）
│     ├─ store.js      全局状态：当前 tab + 分类列表（唯一跨面板共享数据）
│     └─ theme.js / fnos.js / toast.js   主题与通知单例
│
└─ app/（FastAPI + SQLAlchemy，三方言 SQLite/MySQL/PostgreSQL）
    main.py            应用组装：日志初始化、路由挂载（根 + API_BASE_PATH 双前缀）、
    │                  全局异常处理器注册、静态资源与 PWA 路由
    ├─ core/           最底层：errors（错误码+异常族）、context（GatewayUser）、
    │                  handlers（异常→统一响应），不依赖任何业务层
    ├─ api/            路由层：参数校验 + 依赖注入（deps.py），委托 services；
    │                  唯一允许 import fastapi 的业务层
    ├─ services/       业务层：校验与流程编排，只抛 core.errors 异常族
    ├─ db/             engine（引擎/会话）· migrations（schema 迁移）· base（门面）
    │                  · models（ORM）· copy（跨库搬移）· dao/（数据访问，静态方法）
    ├─ parsers/        账单解析：base（抽象基类+方向映射）· csv_common（编码/金额/列头）
    │                  · __init__（平台注册表 PARSERS）· detect（来源识别）
    └─ utils/          纯工具：amount / period / filters / file_utils / category_matcher
                       / region_matcher / city_geo（不依赖 Web 框架）
```

**分层依赖方向（单向，禁止反向）**：

```
core ← utils ← parsers ← db(dao) ← services ← api ← main
                  ↑           ↑
              db/models    core/context（GatewayUser 下沉后服务层可引用）
```

- `core/` 是最底层，全部分层可引用；`db/utils/parsers/services` **运行期不得 import fastapi**
  （`utils/file_utils.py` 的 UploadFile 仅作 TYPE_CHECKING 类型标注）。
- 历史兼容：`app/db/base.py` 保留为门面，再导出 engine/migrations 的公开符号，
  外部统一 `from app.db.base import ...`；`_STATE` 等测试钩子亦从 base 导入。

## 2. 统一接口契约

### 2.1 统一响应结构

除文件下载端点（导出 xlsx/csv、备份 JSON、日志文件，返回二进制不走包装）外，
**所有接口返回统一结构**：

```jsonc
// 成功（HTTP 2xx）
{ "code": 0, "msg": "ok", "data": <业务数据，可能为对象/数组/null> }
// 失败（HTTP 4xx/5xx，data 恒为 null）
{ "code": 40002, "msg": "交易单号已存在", "data": null }
```

- 实现位置：`app/schemas/common.py::ApiResponse[T]`（路由 response_model 显式声明）
  + `app/core/handlers.py`（全局异常处理器）。
- HTTP 状态码保留语义：400 参数/冲突、403 权限、404 不存在、422 请求体校验、500 内部错误。
- 204（DELETE）无响应体，不包装。

### 2.2 统一错误码（`app/core/errors.py::ErrorCode`）

| 分段 | 含义 | 常量举例 |
| --- | --- | --- |
| 0 | 成功 | `OK` |
| 100xx | 通用：参数/权限/不存在/冲突/超限 | `BAD_REQUEST=10001`、`FORBIDDEN=10002`、`NOT_FOUND=10003`、`CONFLICT=10004`、`UPLOAD_TOO_LARGE=10005` |
| 400xx | 账单流水 | `BILL_INVALID=40001`、`BILL_TX_ID_DUP=40002` |
| 410xx | 消费分类 | `CATEGORY_INVALID=41001` |
| 420xx | 导入/解析 | `IMPORT_PARSE_FAILED=42001`、`IMPORT_SOURCE_UNKNOWN=42002` |
| 430xx | NAS 导入 | `NAS_DIR_INVALID=43001` |
| 440xx | 预算 | `BUDGET_INVALID=44001`、`BUDGET_NOT_FOUND=44002` |
| 450xx | 资产快照 | `ASSET_INVALID=45001`、`ASSET_NOT_FOUND=45002` |
| 470xx | 设置/数据库 | `DB_CONFIG_INVALID=47001`、`DB_MIGRATE_FAILED=47002`、`LOG_NOT_FOUND=47003` |
| 480xx | 智能分类（AI） | `AI_NOT_CONFIGURED=48001`、`AI_CALL_FAILED=48002` |
| 50000 | 服务器内部错误 | `INTERNAL_ERROR`（未预期异常，堆栈入运行日志，对外只返回通用文案） |

新增错误码时按所属域取下一空号；跨域通用错误用 100xx。

### 2.3 异常协议

- 服务层/DAO 层只抛 `core.errors` 异常族：`ValidationError(400)`、`PermissionDeniedError(403)`、
  `NotFoundError(404)`、`ConflictError(400)`、`UploadTooLargeError`、`ImportParseError`、
  `ConfigError`、`EnvironmentError_(500)`、`AIClientError(BizError 子类)`。
- **路由层不写 try/except 翻译**；全局处理器统一转统一响应体。
- DAO 写入的「唯一约束兜底」：`db/engine.translate_unique_violation()` 把并发下越过的
  IntegrityError 转为 `ConflictError`（修复了原 `UniqueViolationError` 从未被抛出、
  并发冲突实际返回 500 的缺陷）。
- 导入管线区分两类失败：文件内容问题（`ImportParseError` → 400）与环境问题
  （`EnvironmentError_` → 500），其余未预期异常由全局处理器转 500 并记录堆栈，
  不再伪装成"解析失败"。

### 2.4 前端请求约定

- `src/api/client.js::api()` 是唯一请求封装：统一解包 `data`、非 2xx 抛
  `Error(msg)`（`err.code` 附错误码）、默认 30s 超时（`AbortSignal.timeout`，
  上传/AI/迁移等长请求按端点放宽）、兼容旧 `{detail}` 错误结构。
- 组件**不直接拼接口路径**，一律 `import { xxx } from "../api/<域>"`（bill/stat/
  category/budget/asset/upload/settings/ai，`index.js` 为汇总出口）。
- 下载类端点（导出/备份/日志下载）由 api 层提供 `xxxUrl()` 生成链接，浏览器直接下载。

## 3. 分层与命名规范

### 3.1 后端

| 层 | 目录 | 职责 | 禁止 |
| --- | --- | --- | --- |
| core | `app/core/` | 错误码、异常族、请求上下文、异常→HTTP 适配 | 依赖任何业务层 |
| utils | `app/utils/` | 纯函数工具（金额/周期/筛选/文件头） | 运行期依赖 Web 框架、写库 |
| parsers | `app/parsers/` | 账单文件解析，平台注册表 `PARSERS` 单一来源 | 反向依赖 services |
| db | `app/db/` | 引擎/迁移/ORM/DAO；DAO 静态方法 + user_id 隔离 | 依赖 services/api |
| services | `app/services/` | 业务校验与流程，异常语义化 | 抛 HTTPException、import fastapi |
| api | `app/api/` | 参数校验、依赖注入、`ok()` 包装返回 | 业务逻辑、写库 |

命名：模块 snake_case；DAO 类静态方法；服务层模块级函数；常量全大写并**单一来源**
（如 `TAGS_MAX_LENGTH` 定义于 models、`CATEGORY_NAME_MAX_LENGTH` 定义于 schema，
两处校验共享同一常量）。周期计算一律用 `app/utils/period.py`，金额取整一律用
`app/utils/amount.py::round2`，附件下载头一律用 `app/utils/file_utils.py::content_disposition`。

### 3.2 前端

| 目录 | 职责 |
| --- | --- |
| `src/api/` | 按域端点模块 + client 封装（唯一 fetch 出口） |
| `src/composables/` | 组合式函数：`useChart(el, render, {canRender})` 统一 init/resize/dispose/主题重绘；`useConfirm` 提供 Promise 风格应用内确认弹窗 |
| `src/utils/` | format（金额/类型/标签）、datetime（本月/本年窗口、nowLocalMinute）、constants（ACCOUNTS/TX_TYPES/PLATFORMS/SOURCE_META）、charts/chartTheme |
| `src/components/<域>/` | 大面板按业务域拆分：`settings/`（Database/AI/Backup/Logs/AppearanceAbout）、`import/`（NasImportBox/PlatformUploadGrid） |
| `src/store.js` | 全局态仅存 tab 与分类列表；服务端数据归各组件本地 |

确认交互一律 `await confirm({title, message, danger})`（App.vue 挂载 `<AppConfirm/>`），
**禁止使用原生 `confirm()`**。图表组件一律经 `useChart`，热力色一律 `heatRamp()`，
tooltip 金额一律 `fmtMoney`。

### 3.3 工具链

- 后端：`pytest`（236 用例，`pytest.ini` 内 DeprecationWarning 升级为 error）、
  `ruff check app/ tests/ --select F,E7,E9,W6`。
- 前端：ESLint 9（flat config，`eslint-plugin-vue` recommended）+ Prettier；
  `npm run lint` / `npm run lint:fix` / `npm run format`；`npm run build` 产出至 `app/static`。
- Service Worker 版本：`vite.config.js::bump-sw-version` 插件在每次构建后把
  `app/static/sw.js` 的 `SW_VERSION` 写为构建时间戳，不再手工递增。

## 5. 修复的真实缺陷（行为修正项）

以下三处是重构过程中确认并修复的**缺陷**（非纯结构改动）：

1. **唯一约束兜底从未生效**（`app/db/base.py` 原 `UniqueViolationError`）：
   DAO 走 ORM，冲突抛的是 SQLAlchemy `IntegrityError`，服务层 `except UniqueViolationError`
   永不命中——并发重复交易号/重名分类实际返回 500。现由
   `translate_unique_violation` 统一转译为 `ConflictError`（HTTP 400 + 40002/41001）。
2. **消费日历边界串月**（`stat_service.daily_heatmap`）：传给 DAO 的"次月 1 号"
   排他上界被 `build_criteria` 按"含当日"语义处理，导致某月热力图包含下月 1 号、
   全年热力图包含次年 1 号的数据。现改用 `period.month_range/year_window` 的含当日边界。
3. **heatRamp 亮色主题方向颠倒**（`utils/chartTheme.js`）：文档约定"浅色主题低值淡、
   高值浓"，实际输出相反（低值最深）。已按 pine 令牌重排为「低值近纸色 → 高值浓墨绿」，
   深色主题为「低值近底色 → 高值亮绿」；消费日历与消费地图共用同一色阶。

## 6. 影响范围与兼容性

| 范围 | 说明 |
| --- | --- |
| API 响应结构 | **破坏性变更**：所有 JSON 接口改为 `{code,msg,data}` 包装（下载端点除外），前后端同步升级；第三方若直连旧接口需按新结构解析 |
| HTTP 状态码 | 不变（400/403/404/422/500 语义保留） |
| 业务字段 | 各端点业务数据字段与原有一致（`CategoryDeleteResult` 补充了此前未声明的 `moved_bills` 契约） |
| 数据库 | schema 不变（仍为 v3），无迁移；`db/base.py` 门面再导出保持 import 兼容 |
| 前端交互 | 确认弹窗由原生阻塞式改为应用内 Promise 弹窗，交互观感升级、流程不变 |
| 打包 | `npm run build` 产物仍输出 `app/static`；SW 版本号自动维护；新增 devDependencies（eslint/prettier 等）不进入运行时 |
| 配置 | 环境变量/向导参数/db·ai·nas 配置文件格式均不变 |
